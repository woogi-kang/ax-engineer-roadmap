> 공개 사례 연결: G11의 OCR·민감정보·근거 문서·전문가 승인 패턴을 [공개 사례 적용 맵](../../research/public-case-application-map.md)에서 증빙 추출과 회계 검토 질문으로 연결했다.

법인카드 내역과 영수증을 모으는 일은 비교적 쉽게 자동화할 수 있다. 어려운 부분은 어떤 증빙이 빠졌는지, 회사 규정과 맞지 않는 지출은 무엇인지, 누가 계정과목과 비용 귀속을 확정할지 정하는 일이다.

## 현재 실행물과 근거

현재 공개한 근거는 시뮬레이션 설계 문서다. 합성 카드 내역과 영수증을 전제로 하며, 실제 회계 시스템에 전표를 게시하거나 세무 처리를 결정하지 않는다.

## 1. 사례 성격

- 유형: 업무 흐름
- 도메인: 재무·구매
- 연습 범위: P1~P3
- 외부 영향: 전표 초안까지만 작성

## 2. 문제와 사용자

| 항목 | 내용 |
|---|---|
| 시작 사건 | 카드 승인 내역 수신, 개인 경비 청구, 영수증 제출 |
| 주요 사용자 | 지출자, 팀 승인자, 재무·회계 담당자 |
| 업무 책임자 | 사용 목적은 지출자, 예산·정책 승인은 팀 책임자, 계정과목·회계 처리는 재무 담당자 |
| 자주 생기는 문제 | 증빙 누락, 금액 불일치, 중복 제출, 비용 귀속 오류, 마감 직전 수정 집중 |
| 실패 피해 | 잘못된 전표, 재무팀 수정 부담, 결산 지연, 감사 추적 단절 |

## 3. 목표 흐름

```text
카드 거래·경비 요청 수집
→ 영수증과 거래를 후보 매칭
→ 증빙 누락·중복·금액 차이 표시
→ 회사 규정과 예산 기준을 근거와 함께 확인
→ 지출자 보완
→ 팀 승인
→ 재무 담당자가 계정과목·세무 처리를 확인
→ 회계 샌드박스용 전표 초안과 감사 기록 생성
```

## 4. 데이터와 기준 정보

| 정보 | 기준 시스템 | 확인할 품질 |
|---|---|---|
| 카드 거래 | 카드사 내역 또는 비용관리 SaaS | 승인·취소·부분취소, 통화, 가맹점 |
| 영수증·증빙 | 증빙 저장소 | 금액·일자·사업자 정보, 원본 연결 |
| 비용 목적·귀속 | 지출 요청 | 프로젝트·부서·참석자·설명 |
| 회사 규정 | 승인된 정책 문서 | 버전, 적용일, 예외 승인자 |
| 전표 상태 | 회계 샌드박스 | 초안·승인·게시 상태 구분 |

## 5. 통제 경계

- AI는 문서에서 필드를 추출하고 거래 후보를 연결하며 누락과 정책 예외를 표시한다.
- 규정에 없는 사례는 추정하지 않고 재무 검토 대기열로 보낸다.
- 계정과목, 공제 여부, 비용 인정 여부는 담당자가 확정한다.
- 같은 카드 거래와 영수증을 두 전표에 사용하지 못하게 식별자를 유지한다.
- 원본 증빙, 추출값, 사람이 고친 값, 최종 승인값을 구분해 남긴다.

## 6. P1~P3 실습 경로

| 단계 | 실습 | 통과 기준 |
|---|---|---|
| P1 | 합성 영수증에서 필드 추출·거래 매칭 | 누락·중복·취소·외화 평가 통과 |
| P2 | 지출자 보완과 팀·재무 승인 흐름 | 수정 부담과 승인 사유가 측정됨 |
| P3 | 회계 샌드박스용 전표 초안 생성 | 원본 연결, 중복 방지, 실패 복구 시험 |

## 7. 실패 주입과 복구

| 실패 주입 | 확인할 것 | 복구 |
|---|---|---|
| 영수증 금액과 카드 금액이 다름 | 자동 확정을 막는가 | 지출자 보완 요청 |
| 취소 거래가 늦게 들어옴 | 기존 초안을 찾아 상태를 바꾸는가 | 게시 전 취소, 게시 뒤 재무 검토 |
| 같은 영수증을 두 번 제출함 | 문서·거래 중복을 찾는가 | 중복 후보를 묶어 한 건만 유지 |
| 정책 문서가 갱신됨 | 적용일과 버전을 구분하는가 | 당시 적용 정책으로 재평가 |
| 회계 샌드박스 쓰기 실패 | 초안을 다시 만들어 중복시키지 않는가 | 기존 실행 상태 확인 후 재시도 |

## 8. 결과물과 한계

결과물은 합성 거래·영수증 세트, 추출·매칭 평가, 정책 예외 큐, 승인 기록, 전표 초안, 실패·복구 기록이다.

회사별 비용 규정과 회계·세무 처리는 다르다. 이 사례는 어떤 계정과목이나 공제 기준이 정답이라고 제시하지 않으며, 결산 시간이나 비용 누수가 줄었다고 주장하지 않는다.

## 9. 재사용과 다음 결정

문서 추출 결과와 원본의 연결, 거래 중복 방지, 정책 버전, 승인 수정 이력은 전자세금계산서와 거래처 등록 사례에서도 재사용 후보가 된다. 두 번째 업무에서 실제로 사용한 계약만 공통 재무 워크플로우에 포함한다.
