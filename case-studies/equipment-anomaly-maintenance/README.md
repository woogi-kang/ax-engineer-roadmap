# 사례: 설비 이상 신호에서 검토 가능한 정비 제안까지

<!-- case-boundary:start -->
## 현재 범위와 설계 목표

| 구분 | 쓰기 영향 | 자율성 | P 단계 |
|---|---|---|---|
| 현재 공개 실행물 | 외부 쓰기 없음 | A0 | 없음 |
| 설계 목표 | 승인 후 샌드박스 쓰기 | A1-A3 | P1, P2, P3, P4 |

현재 값은 이 저장소에서 재현할 수 있는 범위만 나타낸다. 설계 목표는 아직 구현 범위나 조직 운영 성과가 아니다.
<!-- case-boundary:end -->

합성 센서 스트림에서 이상 후보를 찾고 설비 이력·안전 절차와 연결해 정비 티켓 초안을 만드는 제조 시뮬레이션이다. AI는 설비를 시작·정지·제어하거나 안전 인터록을 바꾸지 않는다.

## 현재 실행물과 근거

현재 근거는 `simulation-design` 문서다. [공개 사례 K06·K07·G03·G04](../../research/public-case-application-map.md)에서 작업자 경고, 예측과 실제 검사 차이, 안전 인터록, 공장별 조건이라는 질문을 가져왔다. 실제 생산 설비에는 연결하지 않았다.

## 1. 사례 성격

| 항목 | 내용 |
|---|---|
| 도메인·산업 | 데이터·운영 / 제조 |
| 위험·설계 목표 자율성 | 높음 / A1–A3 |
| 설계 목표 연습 범위 | P1–P4, 승인 뒤 CMMS 샌드박스 제안 |
| 합성 입력 | 모터 진동·온도·전류 시계열, 센서 단절, 정비 이력, 계획 정지 일정 |

## 2. 문제와 책임

경고 임계값이 너무 낮으면 경보 피로가 생기고 너무 높으면 고장을 놓친다. 정비자는 현장 맥락과 안전 절차를 보고 조사·정비를 결정한다. 설비 책임자는 운전 상태, 안전 담당자는 작업 허가, 정비 책임자는 실제 조치를 소유한다.

## 3. 목표 흐름

```text
합성 센서 사건 수신
→ 센서 상태·시각·단위와 설비 ID 확인
→ 정상 기준과 최근 정비·운전 상태 비교
→ 이상 후보와 불확실성 제시
→ 안전 절차·계획 정지·부품 상태 조회
→ 정비자가 조사·보류·거절·티켓 초안 선택
→ 승인된 초안만 CMMS 샌드박스에 기록
→ 실제 티켓 상태와 후속 센서 사건 대조
```

## 4. 데이터와 통제

| 원본 | 필요한 상태 | 통제 |
|---|---|---|
| Historian | 센서값, 단위, 품질, 시각 | 센서 장애를 설비 이상과 구분한다. |
| 설비 레지스트리 | 모델, 위치, 중요도, 구성 | 다른 설비의 기준을 무단 적용하지 않는다. |
| CMMS | 열린 작업, 정비 이력, 부품 | 이미 열린 티켓과 중복 생성하지 않는다. |
| 안전 절차 | 작업 허가, 격리, 비상 절차 | AI 제안이 안전 절차를 대체하지 않는다. |

## 5. 승인·중단 경계

- AI는 이상 후보, 근거 구간과 조사 순서를 제안한다.
- 센서 품질 불량, 설비 ID 불일치, 정상 기준 부재면 고장으로 단정하지 않는다.
- 자동 정지·재시작·제어값 변경·안전 인터록 우회는 항상 금지한다.
- 긴급 안전 임계값은 생성형 모델이 아니라 기존 안전 계층이 처리한다.
- 티켓 생성도 정비자 승인 뒤 샌드박스에서만 수행한다.

## 6. P1–P4와 평가

| 단계 | 실습 | 통과 기준 |
|---|---|---|
| P1 | 정상·이상·센서 장애 합성 시계열 분류 | 고장과 센서 장애 구분, 근거 구간 표시 |
| P2 | 정비자 조사·보류·승인 | 위험 작업 자동 승인 0건, 수정·거절 사유 기록 |
| P3 | CMMS 샌드박스 티켓 초안 | 중복 티켓 0건, 상태 재조회와 부분 실패 복구 |
| P4 | 설비 한 종류의 제한 파일럿 계획 | 오탐·누락 중단 기준, 수동 절차, 책임자 준비 |

오탐률만 보지 않고 누락 비용, 경보당 검토 시간, 중복 티켓, 센서 장애 분리, 계획 정지와의 충돌, 복구 시간을 측정한다.

## 7. 실패 주입과 복구

| 실패 | 기대 동작 | 복구 |
|---|---|---|
| 센서가 고정값을 보냄 | 설비 고장으로 단정하지 않음 | 센서 점검 큐로 분리 |
| 정비 중 이상 신호 | 열린 작업과 함께 표시 | 정비 책임자에게 병합 판단 이관 |
| 승인 중 운전 상태 변경 | 기존 제안을 무효화 | 현재 상태로 재계산·재승인 |
| 티켓 응답 타임아웃 | 성공 처리하지 않음 | CMMS에서 멱등 키 조회 |

## 8. 결과와 한계

결과물은 합성 센서 사건, 설비·센서 데이터 계약, 이상 근거, 승인 기록, CMMS 샌드박스 티켓과 복구 기록이다. 고장·가동중단·수율·정비비 개선 근거는 없다.

## 9. 다음 결정

공개 실행 전에는 설비 전문가가 합성 사건과 경계값을 검토하고, 모델 없이 동작하는 기존 경보·수동 정비 절차가 그대로 유지되는지 확인해야 한다.
