# 사례: 재고 예외에서 발주·창고 이동 제안까지

재고가 기준 아래로 내려갔다고 곧바로 발주하면 과잉 재고나 중복 주문을 만들 수 있다. 현재 재고, 이미 잡힌 주문, 입고 예정, 다른 창고의 가용 수량, 공급사 조건을 함께 보고 담당자가 선택할 수 있는 안을 만드는 것이 이 사례의 범위다.

## 1. 사례 성격과 현재 근거

- 유형: 업무 흐름
- 도메인: 데이터·운영
- 현재 단계: 시뮬레이션 설계
- 연습 범위: P1~P4
- 외부 영향: 승인 뒤 구매·창고 샌드박스에 제안만 기록

합성 재고·주문·공급사 데이터를 사용한다. 실제 발주, 생산 계획, 창고 이동을 실행하지 않는다.

## 2. 문제와 사용자

| 항목 | 내용 |
|---|---|
| 시작 사건 | 안전재고 하회, 주문 급증, 입고 지연, 특정 창고 품절 위험 |
| 주요 사용자 | 재고 담당자, 구매 담당자, 물류 운영자, 영업·수요 계획 담당자 |
| 업무 책임자 | 재고 상태는 운영, 구매 조건은 구매, 고객·채널 우선순위는 영업·운영 책임자 |
| 자주 생기는 문제 | 오래된 재고 스냅샷, 이동 중 수량 누락, 중복 발주, 공급사 리드타임 변경, 품목 대체 규칙 누락 |
| 실패 피해 | 품절, 과잉 재고, 긴급 배송비, 창고 간 불균형, 공급사 주문 취소 |

## 3. 목표 흐름

```text
재고 예외 사건 수신
→ 재고·예약·이동·발주·입고 예정 상태 재조회
→ 데이터 시점과 품목 식별자 확인
→ 발주·창고 이동·보류 후보 비교
→ 근거와 예상 영향을 담당자에게 제시
→ 금액·수량·품목 기준에 맞는 승인
→ 샌드박스에 제안 기록
→ 실제 기록 상태와 후속 사건 확인
```

## 4. 시스템별 기준 정보

| 시스템 | 기준으로 삼을 정보 | 주의할 점 |
|---|---|---|
| ERP | 품목, 구매 주문, 회계상 재고 | 실시간 창고 상태와 다를 수 있음 |
| WMS | 창고별 가용·예약·이동 수량 | 품목 마스터와 식별자를 맞춰야 함 |
| 주문 시스템 | 확정 주문과 취소 상태 | 수요 예측과 실제 주문을 구분 |
| 공급사·구매 시스템 | 리드타임, 최소 주문량, 기존 발주 | 최신 조건 확인 필요 |
| 운영 원장 | 제안·승인·실행·대조 사건 | 원본 시스템의 수량을 대신하지 않음 |

## 5. 통제 경계

- AI는 예외 원인을 정리하고 발주·이동·보류 후보를 비교한다.
- 데이터 시점이 허용 범위를 넘으면 제안을 만들지 않고 새로 조회한다.
- 이미 발주했거나 이동 중인 수량을 중복해서 제안하지 않는다.
- 금액·수량·안전 영향이 큰 제안은 추가 승인자를 요구한다.
- 자동 발주, 공급사 변경, 품목 대체, 고객 주문 취소는 범위에서 제외한다.
- 승인 뒤 원본 상태가 바뀌면 실행 전에 다시 계산하고 승인도 다시 받는다.

## 6. P1~P4 실습 경로

| 단계 | 실습 | 통과 기준 |
|---|---|---|
| P1 | 합성 스냅샷에서 재고 예외와 후보 찾기 | 오래된 데이터·음수 재고·중복 발주 평가 통과 |
| P2 | 담당자가 근거와 대안을 비교하는 승인 흐름 | 수정·보류·거절 사유 기록 |
| P3 | 구매·WMS 샌드박스에 제안 기록 | 멱등 쓰기, 상태 재조회, 부분 실패 복구 |
| P4 | 제한된 품목군 파일럿 계획 | 중단 임계값, 수동 발주, 사후 대조 기준 준비 |

## 7. 실패 주입과 복구

| 실패 주입 | 확인할 것 | 복구 |
|---|---|---|
| 재고 스냅샷이 오래됨 | 제안을 중단하는가 | 원본 재조회 |
| 발주가 이미 생성됨 | 중복 제안을 막는가 | 기존 발주와 연결 |
| 승인 중 주문이 급증함 | 오래된 계산을 버리는가 | 새 상태로 재계산·재승인 |
| 창고 이동만 성공함 | 부분 실행을 보이는가 | 발주 후보 보류·운영자 확인 |
| 공급사 리드타임이 바뀜 | 기존 제안을 다시 평가하는가 | 대안 공급사 판단은 구매 담당자에게 인계 |

운영 지표는 AI 추천 채택률만 보지 않는다. 오래된 데이터 차단률, 중복 제안, 담당자 수정량, 부분 실패, 수동 복구 시간, 원본과의 사후 불일치를 함께 본다.

## 8. 결과물과 한계

공개 결과물은 합성 재고 사건, 데이터 계약, 후보 비교표, 승인 기록, 샌드박스 쓰기와 실패·복구 기록이다.

실제 품절, 재고 회전, 서비스 수준, 구매 비용이 개선됐다는 근거는 없다. 안전재고, 리드타임, 대체품, 배분 우선순위는 조직과 품목에 맞게 다시 정해야 한다.

## 9. 재사용과 다음 결정

상태 재조회, 스냅샷 시점, 멱등 제안, 금액·수량별 승인, 부분 실패 원장은 다른 운영 업무에서도 재사용할 수 있다. 실제 두 번째 운영 업무에서 확인한 뒤 공통 실행 계층에 포함한다.
