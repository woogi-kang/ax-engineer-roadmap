# 사례: 거래처 등록·계좌 변경을 검증 가능한 승인 흐름으로

거래처 정보와 지급 계좌는 한 번 바뀌면 이후 여러 지급에 영향을 준다. 이 사례는 서류를 읽는 자동화보다, 요청자·검증자·승인자·실행자를 나누고 변경 근거와 실제 반영 결과를 추적하는 데 초점을 둔다.

## 현재 실행물과 근거

현재 공개한 근거는 시뮬레이션 설계 문서다. 실제 거래처나 계좌의 소유권을 확인하지 않으며, 운영 ERP의 지급 정보를 바꾸지 않는다.

## 1. 사례 성격

- 유형: 업무 흐름
- 도메인: 재무·구매
- 연습 범위: P1~P4
- 외부 영향: 이중 승인 뒤 거래처 마스터 샌드박스에만 쓰기

## 2. 문제와 사용자

| 항목 | 내용 |
|---|---|
| 시작 사건 | 신규 거래처 등록, 상호·주소·세금 정보 변경, 지급 계좌 변경 |
| 주요 사용자 | 구매 담당자, 현업 요청자, 재무 담당자, 보안·감사 담당자 |
| 업무 책임자 | 거래 필요성은 구매·현업, 서류와 지급 정보는 재무, 최종 마스터 변경은 권한 있는 실행자 |
| 자주 생기는 문제 | 메일 요청만으로 변경, 사업자번호 오류, 서류 버전 불명, 승인자와 실행자 동일, 변경 뒤 대조 누락 |
| 실패 피해 | 오지급, 사기, 지급 지연, 거래처 중복, 감사 추적 단절 |

## 3. 목표 흐름

```text
등록·변경 요청 접수
→ 요청자와 거래 목적 확인
→ 사업자 정보·제출 서류·기존 마스터 대조
→ 계좌 변경은 독립 채널로 재확인
→ 검증자와 승인자의 이중 확인
→ 승인된 변경만 ERP 샌드박스에 반영
→ 변경 전후와 실제 반영 결과 대조
→ 일정 기간 고위험 지급 모니터링
```

## 4. 데이터와 기준 정보

| 정보 | 기준 시스템 | 자동화 경계 |
|---|---|---|
| 거래 목적과 담당자 | 구매 요청 시스템 | 필요성과 예산을 AI가 승인하지 않음 |
| 사업자 상태 | 국세청 상태조회 등 공식 조회 | 정상 상태만으로 거래 적격성을 판단하지 않음 |
| 거래처 마스터 | ERP·구매 시스템 | 변경 전후 버전을 모두 보존 |
| 계좌 증빙 | 제한된 증빙 저장소 | 문서만으로 소유권을 확정하지 않음 |
| 승인·실행 기록 | 독립 감사 저장소 | ERP 로그만으로 대체하지 않음 |

[공공데이터포털의 국세청 사업자등록정보 진위확인·상태조회 서비스](https://www.data.go.kr/data/15081808/openapi.do)는 사업자등록번호 상태 확인에 사용할 수 있다. 이 결과는 거래처 실사나 계좌 소유권 확인을 대신하지 않는다. (2026-07-31 확인)

## 5. 통제 경계

- 메일 본문의 계좌번호만으로 변경 요청을 만들지 않는다.
- 요청자, 검증자, 승인자, 실행자의 역할을 분리한다.
- 계좌 변경은 등록된 담당자나 계약상 연락처 등 독립된 경로로 다시 확인한다.
- AI는 서류의 필드와 불일치를 정리할 수 있지만 거래 적격성이나 사기 여부를 판정하지 않는다.
- 승인 뒤 서류나 계좌가 바뀌면 기존 승인을 무효화한다.
- 변경 직후 고액 지급은 별도 승인이나 보류 규칙을 적용한다.

## 6. P1~P4 실습 경로

| 단계 | 실습 | 통과 기준 |
|---|---|---|
| P1 | 합성 등록·변경 요청에서 누락·충돌 찾기 | 중복 거래처, 잘못된 번호, 오래된 서류 평가 통과 |
| P2 | 검증·승인 역할이 분리된 대기열 | 우회 승인과 자기 승인 차단 |
| P3 | 거래처 마스터 샌드박스 변경 | 변경 버전, 멱등 쓰기, 부분 실패 복구 시험 |
| P4 | 제한된 파일럿 계획 | 독립 재확인, 지급 보류, 수동 처리 기준 준비 |

## 7. 실패 주입과 복구

| 실패 주입 | 확인할 것 | 복구 |
|---|---|---|
| 기존 거래처와 사업자번호가 같음 | 중복 등록을 막는가 | 기존 마스터와 병합 검토 |
| 계좌 변경 메일이 위조됨 | 독립 재확인 전 쓰기를 막는가 | 요청 폐기, 보안 담당자 인계 |
| 승인 뒤 계좌가 다시 바뀜 | 기존 승인을 무효화하는가 | 새 버전으로 이중 승인 |
| ERP 반영 중 일부 필드만 바뀜 | 부분 성공을 찾는가 | 변경 전 스냅샷으로 복원하거나 수동 보정 |
| 실행 로그는 성공이나 실제 값이 다름 | 원본 시스템을 다시 읽는가 | 지급 보류 후 실제 값 교정 |

## 8. 결과물과 한계

공개 결과물은 합성 거래처·서류·변경 요청, 역할 분리표, 불일치 평가, 승인 기록, 샌드박스 변경 전후, 복구 훈련 기록이다.

실제 계좌 소유권, 거래처 신용, 제재 여부, 계약 적정성을 검증하지 않았다. 사기 감소나 지급 정확도 개선도 주장하지 않는다.

## 9. 재사용과 다음 결정

마스터 데이터 버전, 독립 재확인, 이중 승인, 변경 직후 보류, 실제 상태 재조회는 지급 정보뿐 아니라 고객 환불 계좌나 임직원 급여 계좌 변경에서도 시험할 수 있다.
