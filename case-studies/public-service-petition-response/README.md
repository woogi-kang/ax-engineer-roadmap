## 현재 범위와 설계 목표

| 구분 | 외부 시스템 변경 범위 | 자율성 | 관련 P 단계 |
|---|---|---|---|
| 현재 공개 결과 | 외부 시스템 변경 없음 | A0 | 없음 |
| 설계 목표 | 초안 전용 | A1-A2 | P1, P2, P3 |

현재 값은 이 저장소에서 재현할 수 있는 범위만 나타낸다. 현재 결과의 P 표시는 해당 단계에 속한 기능이 구현됐다는 뜻이며, 그 단계의 통과 기준을 모두 충족했다는 뜻은 아니다. 설계 목표는 아직 구현 범위나 조직 운영 성과가 아니다.
<!-- case-boundary:end -->

현재 공개물은 설계 문서와 메타데이터다. 아래 문제·현재 흐름은 실습을 위한 가정이며 입력 세트, 실행 코드, 실행 로그와 검수 결과는 아직 공개하지 않았다. 목표 흐름·평가·결과물은 앞으로 구현하고 확인할 항목이다.

사례별 P 단계 표는 [프로젝트 공통 통과 기준](../../projects/README.md)에 더할 조건이다. P1의 최소 평가 수와 독립 검수를 생략하지 않으며, P4 계획이나 준비 문서만으로 운영 파일럿을 통과했다고 표시하지 않는다.

합성 민원을 법령·정책·기존 답변과 연결해 초안을 만들고, 비슷한 민원 묶음을 담당자가 검토하는 시뮬레이션이다. AI가 대외 답변을 발송하거나 민원을 임의로 종결하지 않는다.

## 현재 공개 결과와 근거

현재 근거는 `simulation-design` 문서다. [공개 사례-실습 연결표](../../research/public-case-application-map.md)의 K01은 답변 문장별 출처와 유사 민원의 담당자 분리·병합 검토에, K04는 담당자 수정·승인 절차에 반영했다. G12의 낮은 민감도부터 시작하는 방식과 G15의 복잡 민원 상담사 인계는 자동 발송·종결을 막는 조건으로 사용했다. 실제 기관 시스템이나 시민 데이터는 사용하지 않았다.

## 1. 사례 성격

| 항목 | 내용 |
|---|---|
| 도메인·산업 | 고객·매출 / 공공 |
| 위험·설계 목표 자율성 | 높음 / A1–A2 |
| 설계 목표 연습 범위 | P1–P3, 답변 초안 전용 |
| 합성 입력 | 생활소음, 식품 표시, 도로 파손, 복지 자격 문의와 의도적으로 중복된 민원 |

## 2. 문제와 책임

담당자는 민원 요지, 적용 기관, 법령과 정책, 과거 답변을 따로 찾는다. 비슷해 보이지만 주소·기간·처분 대상이 다른 민원을 잘못 묶으면 답변 누락이나 권리 침해가 생긴다. 업무 책임자는 답변 담당자이며, 정책 소유자는 근거의 최신성과 적용 범위를 확인한다.

## 3. 목표 흐름

```text
합성 민원 접수
→ 개인정보·관할·긴급성 검사
→ 유효한 법령·정책·기존 답변 검색
→ 문장별 출처가 있는 답변 초안
→ 유사 민원 후보와 묶은 이유 제시
→ 담당자가 수정·분리·병합·거절
→ 승인된 초안만 민원 샌드박스에 기록
→ 처리 상태와 이의 제기 가능 경로 확인
```

## 4. 데이터와 통제

| 원본 | 필요한 상태 | 통제 |
|---|---|---|
| 민원 샌드박스 | 원문, 접수 시각, 관할, 상태 | 원문과 요약을 분리하고 민감정보를 최소화한다. |
| 법령·정책 말뭉치 | 조문, 시행일, 관할, 폐기 여부 | 시행일이 맞지 않으면 인용하지 않는다. |
| 기존 답변 저장소 | 답변, 근거, 승인자, 당시 정책 버전 | 선례가 현재에도 유효하다고 자동 가정하지 않는다. |
| 감사 원장 | 초안 버전, 군집 변경, 승인·거절 | 승인 전 발송과 자동 종결을 금지한다. |

## 5. 승인·중단 경계

- AI는 요약, 검색, 초안과 군집 후보만 제안한다.
- 긴급 안전, 법적 불복, 아동·자해, 수사 관련 신호는 일반 큐에서 제외해 사람에게 즉시 넘긴다.
- 답변 문장에 유효한 출처가 없거나 출처끼리 충돌하면 초안을 완료하지 않는다.
- 군집은 동일 답변 대상을 보장하지 않는다. 담당자가 각 민원을 분리해서 볼 수 있어야 한다.
- 사람 승인 없이는 외부 발송, 상태 변경, 일괄 종결을 하지 않는다.

## 6. P1–P3와 평가

| 단계 | 실습 | 통과 기준 |
|---|---|---|
| P1 | 30개 이상의 합성 민원에서 검색·요약·군집 후보 생성 | 모든 주장에 출처, 관할·시행일 오류 거절, 긴급 사례 이관 |
| P2 | 담당자 수정·분리·병합·승인 화면 또는 기록 | 승인 없는 발송 0건, 군집 변경 이력 100% |
| P3 | 승인 초안을 민원 샌드박스에 멱등 기록 | 중복 기록 0건, 타임아웃 뒤 실제 상태 재조회 |

정확도 하나가 아니라 출처 누락, 잘못 묶인 비율, 담당자 수정량, 긴급 이관 누락, 중복 기록과 복구 시간을 측정한다.

## 7. 실패 주입과 복구

| 실패 | 기대 동작 | 복구 |
|---|---|---|
| 폐기된 정책이 검색됨 | 초안을 중단하고 충돌 표시 | 정책 소유자가 유효 버전 지정 |
| 주소가 다른 민원이 같은 군집에 들어감 | 자동 일괄 처리를 막음 | 담당자가 분리하고 규칙 기록 |
| 문서 안 악성 지시문 | 자료로만 취급 | 해당 출처 격리·재평가 |
| 기록 응답 전 타임아웃 | 성공으로 표시하지 않음 | 민원 샌드박스 재조회 후 재시도 |

## 8. 결과와 한계

공개할 자료는 합성 민원 세트, 출처가 있는 초안, 군집 검토 기록, 승인 기록과 실패·복구 기록이다. 실제 민원 처리 시간, 답변 정확도, 시민 만족도가 개선됐다고 주장하지 않는다.

## 9. 다음 결정

공개 실행으로 승격하려면 합성 평가 세트와 군집 정답·경계 사례를 공개하고, 별도 검토자가 긴급 이관과 출처 유효성을 재평가해야 한다.
