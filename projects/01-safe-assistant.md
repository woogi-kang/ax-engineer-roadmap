# 프로젝트 1. 안전한 보조 도구

## 목표

공개·합성 데이터만 사용하고 외부 업무 시스템을 변경하지 않는 보조 도구를 만든다. 답변 생성보다 출처 표시, 거절 조건, 평가 결과와 한계를 먼저 확인한다.

## 추천 업무

- 공개 정책·매뉴얼 질의응답
- 공개 VOC 분류와 요약
- 합성 회의 기록에서 할 일 초안 만들기
- 공개 상품 정보 비교표 초안

고객·직원 개인정보, 영업 기밀과 운영 업무 계정은 사용하지 않는다. P1의 `외부 실행 없음`은 고객 대상 발송·게시나 업무 시스템 쓰기를 하지 않는다는 뜻이다.

허용된 로컬 모델이나 모델 API에 공개·합성 입력을 보내 추론 응답을 받는 처리 요청은 업무 실행과 구분한다. API를 사용한다면 테스트 계정과 모델의 사용 권한, 데이터 전송·보관·학습 조건, 비용 한도를 먼저 확인한다. 모델 API에 연결해도 업무용 도구의 발송·쓰기 권한은 추가하지 않는다. 규칙 기반 방식과 LLM 방식은 이 처리 범위 안에서 비교한다.

## 업무 흐름

```text
질문 또는 문서 입력
→ 입력 범위 확인
→ 검색·분류·생성
→ 출처와 불확실성 표시
→ 담당자 검수
→ 결과와 수정 이유 기록
```

## 해야 할 일

1. 사용자와 완료 기준을 도구 이름 없이 정의한다.
2. 규칙 기반 방식과 LLM 방식을 비교한다.
3. 공개·합성 데이터의 출처와 누락을 기록한다.
4. 정상·경계·실패 사례를 최소 20개 만든다.
5. 답할 수 없는 질문, 출처 충돌, 금지 입력을 거절하게 한다.
6. 비용·지연·품질을 같은 실행 단위로 기록한다.
7. 다른 사람이 판정 기준으로 결과를 검수한다.

## 역할별 수행

- 비개발 실무자: 사례, 검수 기준, 금지 질문, 수정 이유를 만든다.
- AX 엔지니어: 검색·생성·구조화 출력·평가 실행을 구현한다.
- 리더·거버넌스: 범위, 중단 기준, 공개 범위를 승인한다.
- 데이터·보안·운영: 데이터 출처, 저장 금지, 기록 범위를 확인한다.

## 확인할 결과

- 현재와 목표 업무 흐름
- 데이터 출처와 사용 범위
- 평가 세트와 판정 기준
- 기준선·모델 방식 비교
- 출처·거절·불확실성 화면 또는 문서
- 비용·지연·품질 결과
- 실패 사례와 다음 결정

## 통과 기준

- 외부 업무 시스템을 변경하거나 고객 대상 발송·게시를 하지 않는다.
- 결과의 출처와 적용 범위를 사용자가 확인할 수 있다.
- 정상·경계·실패를 포함한 최소 20개 평가 사례를 실행했다. 사례 수만 채우지 않고 출처·거절·실패 조건을 함께 확인했다.
- 금지·미확인 질문을 추측으로 채우지 않는다.
- 구현자가 아닌 판정자가 결과와 한계를 확인했다.

## 새 입력으로 독립 검수

개발에 쓰지 않은 정상·경계·실패 입력을 검토자가 준비한다. 출처가 충돌하거나 정보가 부족한 입력도 넣고 답변 내용과 거절 판단을 함께 평가한다. 구현자의 설명 없이 결과와 원문을 비교할 수 있어야 한다.

첫 평가 결과를 남긴 뒤 수정하고 기존 실패와 새 입력을 다시 평가한다. 통과 여부, 수정 이유, 미해결 한계를 구분해 기록한다. 평가 항목 추가만으로 해당 사례의 구현 단계가 올라가지는 않는다.

## 중단 조건

- 비공개 데이터가 입력된다.
- 출처 없는 답을 사실처럼 반복한다.
- 평가 사례의 실패가 사용자에게 숨겨진다.
- 비용·지연 한도를 기록할 수 없다.
