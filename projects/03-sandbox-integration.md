# 프로젝트 3. 샌드박스 통합

## 목표

테스트 환경의 기존 시스템과 연결해 읽기·쓰기, 권한, 중복, 부분 실패, 복구를 검증한다. 실제 고객·금전·운영 데이터에는 영향을 주지 않는다.

## 추천 구성

- 테스트 CRM에서 고객 상태 조회·메모 추가
- 테스트 주문 시스템에서 배송 상태 변경
- 샌드박스 협업 도구에서 승인된 메시지 전송
- 합성 데이터베이스에서 작업 생성·상태 변경

## 업무 흐름

```text
승인된 요청
→ 권한·스키마·중복 검사
→ 샌드박스 실행
→ 결과 확인
→ 부분 성공 대사
→ 완료 또는 사람 인계
```

## 해야 할 일

1. 테스트와 실제 계정·데이터·시크릿을 분리한다.
2. 조회 도구와 변경 도구를 분리한다.
3. 실행 키와 상태 전이를 정의한다.
4. 타임아웃, 권한 거부, 부분 성공, 중복 요청, 외부 장애를 주입한다.
5. 자동 재시도, 사람 인계, 즉시 중단을 실패 유형별로 정한다.
6. 이전 상태 복원과 수동 대체를 실제로 실행한다.
7. 구현자 외 운영자가 로그를 보고 대표 장애를 처리한다.

## 역할별 수행

- 비개발 실무자: 부분 성공의 업무 의미와 수동 처리 우선순위를 정한다.
- AX Builder: 통합, 상태, 중복 방지, 복구를 구현한다.
- 리더·거버넌스: 실제 운영으로 이동할 위험 허용 기준을 정한다.
- 데이터·보안·운영: 계정·권한·로그·장애 훈련을 검증한다.

## 제출 증거

- 샌드박스 격리 설명
- API·이벤트·상태 계약
- 역할·서비스 계정 권한표
- 중복 방지와 부분 실패 시험
- 로그·메트릭·트레이스 또는 동등한 실행 기록
- 롤백·수동 대체·대사 기록
- 운영 인수인계 확인

## 통과 기준

- 테스트 요청이 실제 환경에 도달할 수 없다.
- 같은 실행 키를 반복해도 외부 부작용이 중복되지 않는다.
- 부분 성공 상태를 숨기지 않고 대사할 수 있다.
- 자동 재시도 조건과 중단 조건이 다르다.
- 구현자 없이 대표 장애를 진단·복구했다.

## 중단 조건

- 테스트와 실제 계정의 경계가 불분명하다.
- 외부 실행 결과를 확인하지 않고 성공으로 기록한다.
- 롤백이 다른 유효한 변경을 덮어쓴다.
- 로그 없이는 누락·중복을 찾을 수 없다.
