# 프로젝트 4. 운영 파일럿

## 목표

실제 조직에서는 위험이 낮은 업무 하나를 골라 제한된 사용자만 참여하는 환경에서 운영한다. 공개 시뮬레이션에서는 운영 조건과 장애 대응을 재현하되 실제 업무에서 사용됐거나 조직 성과를 냈다고 주장하지 않는다.

## 진입 조건

두 트랙 모두 P1~P3 통과 근거, 기준선, 성공·중단 조건이 필요하다. 평가, 승인, 권한, 로그, 복구와 수동 대체는 샌드박스에서 실제로 시험하고 구현자 외 검토자가 확인한다. 공통 조건이 빠지면 앞 프로젝트에서 보완한다.

| 항목 | 조직 실전 | 공개 시뮬레이션 |
|---|---|---|
| 책임과 승인 | 실제 업무·데이터·배포·중단 책임자와 대상별 승인 | 시험 운영자·검토자를 지정하고 모의 역할의 판단 범위를 기록. 실제 조직 승인으로 사용하지 않음 |
| 환경과 데이터 | 승인된 제한 운영 환경과 허용 데이터 | 운영과 격리된 실행 환경, 공개·합성 데이터와 합성 트래픽 |
| 개인정보·보안·법무 | 담당자가 실제 적용 여부와 조건을 확인 | 시험 환경의 데이터·권한 조건은 확인하고 실제 조직 적용은 미검증으로 기록 |
| 사용자와 절차 | 실제 사용자와 이중 운영·SOP 계획 합의 | 독립 검토자가 모의 사용자·운영 역할을 맡고 가정한 SOP·수동 대체를 실제 시험 |

조직 실전 조건이 빠졌다면 운영 배포는 보류한다. 공개 시뮬레이션 조건을 별도로 갖춘 경우에만 그 범위에서 진행한다. 격리된 실행 환경이나 독립 검토자도 없다면 설계·자기 점검까지만 남기고 통과 판정을 보류한다.

## 파일럿 범위

다음 항목을 숫자나 명확한 조건으로 제한한다.

- 사용자와 조직 단위
- 업무 유형과 제외 사례
- 데이터와 원본 시스템
- 읽기·쓰기 권한
- 일일·주간 실행량
- 모델·도구 비용
- 파일럿 기간
- 자동 실행과 담당자 승인 범위

## 해야 할 일

1. 배포 전 기준선과 대표 실패를 다시 측정한다.
2. 승인한 범위에서 사용자와 실행량을 점진적으로 늘린다. 시뮬레이션은 합성 트래픽을 늘려 시험한다.
3. 품질·지연·비용·장애·승인 대기·수정 부담을 관찰한다.
4. 조직 실전은 실제 사용자가, 시뮬레이션은 독립 검토자가 모의 역할로 대표 업무와 예외를 처리한다.
5. 자동 실행 차단, 롤백, 수동 대체 훈련을 한다.
6. 조직 실전은 새 SOP·교육·지원과 인수인계를 운영한다. 시뮬레이션은 문서와 시험 환경으로 이를 재현하고 미검증 조직 조건을 남긴다.
7. 확대·유지·수정·중단 중 하나를 근거로 결정한다.
8. 조직 실전은 기존 절차의 유지·종료 상태를, 시뮬레이션은 가정한 전환 조건을 기록한다.

## 운영 전 반드시 재현할 상황

위험한 장애는 격리된 검증 환경에서 재현한다. 실제 조직 파일럿에서는 승인된 범위 안에서만 중단·복구 훈련을 진행한다.

| 상황 | 통과 기준 |
|---|---|
| 연결 끊김과 재접속 | 대기·실행 상태를 복원하고 외부 변경의 중복 여부를 원본에서 확인 |
| 실행 중 취소 | 화면 표시뿐 아니라 후속 실행을 차단하고 진행 중 작업의 실제 취소·완료 상태를 확인 |
| 정책 서버 장애 | 승인이 필요한 변경을 허용하지 않고 보류·기한·담당자 인계를 기록 |
| 모델·도구·정책 변경 | 변경 전후 회귀 평가와 업무별 검수를 통과한 버전만 적용 |
| 품질·비용 한도 초과 | 사전에 정한 기준으로 범위를 줄이거나 중단하고 이전 버전 또는 수동 절차로 전환 |

정책 서버가 복구돼도 미완료 작업을 곧바로 실행하지 않는다. 최신 권한과 요청 상태를 확인하고 필요한 승인을 다시 받는다. 롤백은 모델뿐 아니라 프롬프트·도구·정책 버전을 함께 확인한다. 이미 끝난 외부 작업은 원본과 대사해 별도로 보정하거나 인계한다.

## 업무 완료 비용과 역할별 검수

같은 기간에 발생한 실패와 재시도도 포함해 모델·도구 사용료, 검수·재작업·운영 비용, 그 기간에 배분한 고정비를 합산한다. 이를 검수에 통과한 완료 업무 수로 나누되 중복 업무는 제외한다. 완료 업무가 0건이면 비용 지표를 산출할 수 없다고 표시하고 지출과 실패 원인을 별도로 남긴다.

관리자는 업무 가치와 허용 위험, 실제 사용자는 품질과 수정 부담, 운영자는 장애 대응과 인수인계를 각각 검수한다. 공개 시뮬레이션은 독립 검토자가 맡은 모의 역할을 밝히고 실제 조직의 판단이나 성과로 보고하지 않는다. 의견이 다르면 차이를 기록하고 누가 어떤 근거로 확대·유지·수정·중단을 결정했는지 남긴다. 정책 예외는 사유, 승인자, 기한, 보완 조치를 기록하고 기한이 지나면 다시 검토한다.

## 확인할 결과

- 파일럿 범위와 승인
- 배포 전 기준선과 평가 결과
- 운영 상태 보고와 SLO
- 사용자 검수·수정·지원 기록
- 장애·중단·복구 훈련
- SOP와 운영 인수인계
- 기존 절차 유지·종료 결정
- 성과·한계·의사결정 기록

## 통과 기준

- 모델 품질과 업무 결과를 따로 설명할 수 있다.
- 조직 실전은 실제 사용자가, 공개 시뮬레이션은 독립 검토자가 대표 정상·예외 흐름을 수행했다.
- 장애가 나도 업무를 계속하고 누락·중복 결과를 확인할 수 있다.
- 조직 실전은 운영을 인계받은 담당자가 있고 시뮬레이션은 구현자 외 검토자가 문서만으로 중단·복구와 수동 대체를 수행했다.
- 사전에 정한 기준과 실제 결과를 검토해 확대·유지·수정·중단 중 하나를 결정한다.

## 공개 시뮬레이션 대안

공통 시험과 시뮬레이션 진입·검수 기준을 모두 충족한 결과만 `P4 시뮬레이션 검증`으로 기록한다. `P4 실전 통과`나 조직 운영 경력과 구분하며 다음을 공개한다.

- 실제 운영 대신 사용한 가정과 모의 역할
- 합성 트래픽과 의도적으로 재현한 장애의 범위
- 사용자 검수 대신 독립 검토자가 확인한 내용
- 실제로 검증하지 못한 현업 사용·보안·법률·조직 조건
- 운영 성과를 주장하지 않는 이유

## 중단 조건

- 심각한 금지 결과나 권한 이상이 발생한다.
- 기준선과 비교할 데이터를 수집할 수 없다.
- 수동 대체가 실제 업무량을 감당하지 못한다.
- 사용자 수정 부담이나 지원 요청이 허용 기준을 넘는다.
- 운영 책임자 없이 파일럿 기간이 연장된다.

## 다음 단계로 가기 전 질문

P4 실전 통과 또는 P4 시뮬레이션 검증 기록과 미검증 범위를 먼저 확인한다. 그다음 [두 번째 업무 재사용](05-second-workflow-reuse.md)에서 재사용할 항목을 시험한다. 문서만 작성했거나 공통 시험에 실패했다면 P5의 실행 검증으로 넘어가지 않는다. 시뮬레이션에서 P5로 이어가도 조직 운영 성과를 주장하지 않는다.
