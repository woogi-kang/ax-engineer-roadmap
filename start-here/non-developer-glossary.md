# 비개발자를 위한 AX 용어 안내

기술 용어를 외우는 것이 목표가 아니다. 어떤 결정과 위험을 가리키는지 이해하면 된다.

| 용어 | 업무에서 뜻하는 것 | 꼭 물을 질문 |
|---|---|---|
| LLM | 문장을 읽고 생성하는 모델. 같은 입력에도 결과가 달라질 수 있다. | 틀린 결과를 누가 어떻게 발견하는가? |
| 프롬프트 | 모델에 주는 지시와 맥락. 업무 규정 전체를 대신하지 않는다. | 규칙이 바뀌면 누가 수정하고 시험하는가? |
| 토큰 | 모델이 텍스트를 처리하고 비용을 계산하는 단위. 글자 수와 정확히 같지 않다. | 입력이 길어질 때 비용과 지연을 어떻게 제한하는가? |
| 컨텍스트 | 모델이 이번 실행에서 참고하는 지시, 문서, 대화, 상태. | 오래되거나 권한 없는 정보가 섞이지 않는가? |
| RAG | 관련 문서를 찾아 모델 입력에 붙이는 방식. 검색 결과가 사실의 원본 자체는 아니다. | 출처, 최신성, 누락을 결과와 함께 보여 주는가? |
| Agent | 목표를 위해 여러 단계로 판단하고 도구를 호출하는 시스템. 자율성의 정도는 설계에 따라 다르다. | 한 번에 할 수 있는 행동과 중단 조건은 무엇인가? |
| Agent Loop | 관찰하고, 다음 행동을 고르고, 실행 결과를 다시 확인하는 반복 구조. | 반복 횟수·비용·권한을 어디서 제한하는가? |
| 도구 호출 | 모델이 검색, 조회, 메시지 전송, 데이터 변경 같은 기능을 요청하는 방식. | 읽기와 쓰기 권한을 나눴는가? |
| API | 시스템끼리 정해진 형식으로 데이터를 읽거나 기능을 실행하는 통로. | 공식 통로인지, 실패와 중복 실행을 처리하는지 확인했는가? |
| MCP | AI 애플리케이션과 외부 도구·데이터 연결 방식을 표준화하려는 프로토콜. | 연결 표준이 접근 권한과 업무 승인을 대신한다고 오해하지 않는가? |
| 스키마 | 입력과 출력에 어떤 항목과 형식이 들어가는지 정한 규격. | 필수값, 허용값, 버전이 정의됐는가? |
| 평가 세트 | 정상·경계·실패 사례와 기대 결과를 모은 검증 자료. | 실제 업무의 어려운 사례와 금지 결과가 포함됐는가? |
| 회귀 평가 | 모델·프롬프트·도구를 바꾼 뒤 기존 동작이 나빠지지 않았는지 다시 시험하는 것. | 변경 전후 결과를 같은 기준으로 비교했는가? |
| 사람 승인 | AI가 제안한 실행을 권한 있는 사람이 근거와 기준을 보고 허용하는 절차. | 승인자가 무엇을 보고 어떤 경우 거절하는가? |
| 최소 권한 | 업무에 꼭 필요한 읽기·쓰기 권한만 주는 원칙. | 조회만 필요한 단계에 변경 권한이 열려 있지 않은가? |
| 샌드박스 | 실제 고객·금전·업무 시스템에 영향을 주지 않는 격리된 시험 환경. | 테스트 데이터와 실제 데이터가 확실히 분리됐는가? |
| 로그 | 누가 언제 어떤 입력과 버전으로 무엇을 실행했고 어떤 결과가 났는지 남긴 기록. | 개인정보를 과도하게 저장하지 않으면서 원인을 추적할 수 있는가? |
| 롤백 | 문제가 생겼을 때 이전 버전이나 절차로 되돌리는 것. | 실제로 되돌려 본 기록이 있는가? |
| 수동 대체 | 자동화가 멈췄을 때 사람이 업무를 이어 가는 공식 절차. | 담당자, 입력 자료, 처리 기한이 정해져 있는가? |
| 하네스 | 입력·출력·평가·승인·기록·복구를 반복해서 적용하는 공통 실행 기반. | 첫 사례의 기술을 강제하는가, 검증된 계약만 재사용하는가? |
