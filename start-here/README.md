# 여기서 시작하기

이 로드맵을 처음부터 끝까지 같은 순서로 읽을 필요는 없다. 먼저 자신의 역할과 조직의 현재 준비 상태를 확인하고, 공통 소양을 거쳐 필요한 트랙으로 들어간다.

```mermaid
flowchart TD
    A["내가 맡은 책임은 무엇인가?"] --> B["조직은 어디까지 준비됐는가?"]
    B --> C["공통 AX 소양 점검"]
    C --> D{"주된 책임"}
    D -->|"업무 정의·검수·채택"| E["비개발 실무자"]
    D -->|"구현·통합·운영"| F["AX Builder"]
    D -->|"우선순위·투자·책임"| G["리더·거버넌스"]
    D -->|"데이터·보안·안정성"| H["데이터·보안·운영"]
```

## 1. 역할을 고른다

[역할 선택 안내](persona-selector.md)는 직함이 아니라 이번 업무에서 맡을 책임을 기준으로 트랙을 고르게 돕는다. 한 사람이 두 개 이상의 트랙을 함께 볼 수 있다.

## 2. 조직 준비도를 확인한다

[조직 준비도 진단](organization-readiness.md)은 현재 업무 기록, 원본 시스템, 권한, 운영 책임을 확인한다. 준비도는 AX 성숙도나 조직의 우열이 아니다. 같은 회사에서도 업무마다 다를 수 있다.

## 3. 공통 AX 소양을 확인한다

모든 역할은 다음 질문에 답할 수 있어야 한다.

- 지금 겪는 문제가 업무 문제인지 AI 문제인지 구분했는가?
- 현재 흐름, 대기, 예외, 인수인계를 그릴 수 있는가?
- 없애거나 표준화할 단계와 사람 판단을 남길 단계를 구분했는가?
- 사실의 기준, 데이터 출처, 누락, 용어 차이를 확인했는가?
- 좋은 결과와 실패 결과를 누가 어떤 기준으로 판정하는가?
- 금지 행동, 승인 지점, 중단·복구·수동 대체가 정해졌는가?
- 사용량과 실제 업무 결과를 따로 측정하는가?
- 결정·변경·승인·실패 기록을 다른 사람이 확인할 수 있는가?

막히는 항목이 많다면 구현보다 [목표와 경계](../delivery-lifecycle/01-outcomes-and-boundaries.md), [업무 지도](../delivery-lifecycle/02-workflow-discovery.md), [데이터와 맥락](../delivery-lifecycle/04-data-and-context.md)부터 시작한다.

## 4. 역할별 트랙으로 들어간다

| 주된 책임 | 추천 트랙 |
|---|---|
| 현업 문제 정의, 검수, SOP, 채택 | [비개발 실무자](../tracks/business-practitioner.md) |
| 소프트웨어, AI, 통합, 배포 | [AX Builder](../tracks/ax-builder.md) |
| 포트폴리오, 투자, 책임 체계 | [리더·거버넌스](../tracks/leader-and-governance.md) |
| 데이터, 개인정보, 보안, 장애 대응 | [데이터·보안·운영](../tracks/data-security-operations.md) |

## 5. 프로젝트로 증명한다

[실습 프로젝트](../projects/README.md)는 안전한 보조 도구부터 두 번째 업무 재사용까지 다섯 단계로 이어진다. 개발 환경이 없는 독자는 문서·표·샌드박스 시뮬레이션으로 같은 판단과 검증 증거를 만들 수 있다.
