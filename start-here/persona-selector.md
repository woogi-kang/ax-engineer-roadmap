# 역할 선택 안내

직함보다 이번 업무에서 실제로 내리는 결정과 책임을 확인한다.

## 빠른 선택

아래에서 자신에게 가장 많이 해당하는 문장부터 확인한다.

| 내가 자주 하는 결정 | 먼저 볼 문서 |
|---|---|
| 시스템을 연결하고, AI 동작을 구현·평가하며, 운영 환경에 배포한다. | [AX 엔지니어 실행 경로](../tracks/ax-builder.md) |
| 어떤 일이 문제인지 설명하고, 결과를 검수하며, 동료가 새 절차를 사용할 수 있도록 검수 기준과 정착 과정을 맡는다. | [현업 실무자 협업 안내](../tracks/business-practitioner.md) |
| 여러 후보의 우선순위와 예산을 정하고, 승인·책임·조달 구조를 만든다. | [리더·의사결정자 협업 안내](../tracks/leader-and-governance.md) |
| 데이터 사용을 승인하고, 접근 권한·개인정보·장애·감사 기준을 정해 점검한다. | [데이터·보안·운영 담당자 협업 안내](../tracks/data-security-operations.md) |

## 역할은 겹칠 수 있다

작은 조직에서는 한 사람이 현업 책임과 AX 구현을 함께 맡을 수 있다. 그렇더라도 결정권은 다음처럼 나눠 적는다.

```text
업무 결과 승인: 고객지원 책임자
데이터 사용 승인: 개인정보 보호책임자
배포와 롤백: 서비스 운영 책임자
모델·프롬프트 변경: AX 엔지니어
기존 절차 종료: 업무 총괄
```

사람 이름 대신 역할을 적는다. 담당자가 바뀌어도 승인과 운영 책임이 남아야 한다.

## 비개발자도 기술 내용을 알아야 하나

코드를 직접 작성할 필요는 없다. 다만 다음 경계는 설명할 수 있어야 한다.

- AI가 답을 제안하는 것과 외부 시스템에서 실행하는 것은 다르다.
- 검색한 문서는 최신 업무 상태의 원본이 아닐 수 있다.
- 모델은 같은 입력에도 다른 결과를 낼 수 있다.
- 승인 버튼이 있어도 승인자가 확인할 근거가 없으면 통제가 아니다.
- 자동화가 멈췄을 때 기존 업무로 돌아갈 방법이 필요하다.

[비개발자를 위한 용어 안내](non-developer-glossary.md)와 [안전한 보조 도구 프로젝트](../projects/01-safe-assistant.md)부터 시작한다.

## 개발자라면 무엇을 더 보나

기존 웹·백엔드·데이터 경험이 있어도 업무 발견, 승인 책임, 현업 정착, 기존 절차 종료에는 별도 역량이 필요하다. [AX 엔지니어 실행 경로](../tracks/ax-builder.md)와 함께 [현업 실무자 협업 안내](../tracks/business-practitioner.md)의 검수·SOP 부분을 확인한다.

## 리더라면 무엇을 만들나

전략 문서에는 첫 업무의 기준선, 중단 조건, 책임 배분, 지원 방식, 두 번째 업무의 재사용 결과를 포함한다. [리더·의사결정자 협업 안내](../tracks/leader-and-governance.md)는 기술 구매보다 조직의 배포 능력을 다룬다.
