# 6. 배포와 운영

## 목적

최소 기능을 갖춘 프로토타입에 인증·권한·관측성·복구·비용 통제를 더해 실제로 운영 가능한 시스템으로 전환한다.

## 주요 작업

1. 운영과 개발 환경, 설정, 시크릿을 분리한다.
2. 인증·인가와 최소 권한을 구현한다.
3. 입력 검증, 중복 방지, 타임아웃, 재시도를 구현한다.
4. 로그·메트릭·트레이스와 감사 기록에 같은 실행 식별자를 남긴다.
5. 품질·지연시간·오류·비용 경보를 정한다.
6. 롤백과 수동 대체 경로를 실행해 본다.
7. 배포·장애·복구·운영 절차를 문서화한다.
8. 장기 작업의 추가 입력·재접속·취소를 시험하고 원본 시스템의 최종 상태를 확인한다.
9. 자격증명 만료·회수와 정책 서버 장애를 재현한다.
10. 같은 업무 범위에서 검수 통과 완료 업무당 총비용을 계산한다.

## 최소 관측 항목

- 업무·상위 실행·하위 에이전트·도구 호출·외부 작업 식별자
- 사용자 또는 시스템 주체
- 입력·출력 규격 버전
- 모델·API·SDK·프롬프트·도구·harness·컨텍스트 정책 버전
- 시작·종료 시간과 상태
- 승인·실행·복구 이벤트
- 오류 유형과 재시도 횟수
- 지연시간, 승인 대기, 검수·재작업 시간과 비용
- 취소 요청, 실제 중단 확인, 원본 최종 상태와 대사 결과

민감한 원문과 결과를 무조건 로그에 저장하지 않는다. 추적 가능성과 데이터 최소화를 함께 설계한다.

## 비용과 변경 판단

[완료 업무당 총비용 정의](../technical-foundations/production-operations.md#완료-업무당-총비용)에 따라 분자에는 실패·재시도·검수·재작업·운영과 기간에 맞춰 배분한 고정비를 포함한다. 분모는 중복을 뺀 검수 통과 완료 업무다. 완료가 0건이면 `N/A`로 표시하고 효율 판단을 보류한다.

배포 전후에는 같은 평가 세트와 권한 조건으로 최종 상태·치명적 실패·반복 결과를 비교한다. 구현자 외의 운영자가 장애를 찾아 중단·대사·복구할 수 있어야 한다. [평가 기준](../technical-foundations/evaluation-and-testing.md#최종-상태와-반복-실행)과 [운영 실습](../technical-foundations/production-operations.md#직접-해볼-것)을 함께 적용한다.

## 산출물

- 제한된 범위로 배포한 기능
- CI/CD와 환경 구성
- 운영 대시보드 또는 상태 보고
- 운영 절차서(runbook)와 장애 대응 절차
- 롤백·복구 훈련 기록
- 완료 업무 수·총비용·배분 기준과 변경 전후 비교
- 재접속·취소·권한 회수·정책 장애 시험 기록

## 통과 기준

- 다른 개발자가 배포 구성을 재현할 수 있다.
- 권한 없는 사용과 시스템 호출이 차단된다.
- 실패 원인과 영향을 같은 식별자로 추적할 수 있다.
- 외부 시스템 장애와 모델 실패를 구분한다.
- 롤백 또는 수동 대체 흐름이 실제로 작동한다.
- 재접속·취소 뒤에도 원본 결과를 확인해 중복·누락을 대사한다.
- 만료·회수한 자격증명과 정책 장애의 처리 기준이 실제 호출에 적용된다.
- 민감정보를 과도하게 저장하지 않고 업무 ID로 하위 실행과 외부 결과를 찾을 수 있다.
- 완료 업무당 총비용의 분자·분모와 누락 비용을 설명할 수 있다.

## 중단 신호

- 운영이 개인 계정과 로컬 환경에 의존한다.
- 장애를 사용자 제보로만 발견한다.
- 모든 오류를 같은 방식으로 자동 재시도한다.
- 비용 한도와 중단 기준이 없다.
- 데이터·보안 책임자가 운영 경계를 확인하지 않았다.
