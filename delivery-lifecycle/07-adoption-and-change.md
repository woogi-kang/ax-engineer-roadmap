# 7. 현업 적용과 역할 전환

## 목적

배포한 기능을 공식 업무에 반영하고 사용자·책임·절차·교육·지원 체계를 함께 바꾼다.

## 주요 작업

1. 실제 사용자가 대표 업무와 예외 업무를 수행하게 한다.
2. 사용자가 결과를 신뢰하는지, 수정 부담이 어느 정도인지, 접근성과 기존 절차에 문제가 없는지 확인한다.
3. 교육·지원·장애 문의 경로를 운영한다.
4. 업무 책임자·운영자·데이터 소유자·승인자 역할을 확정한다.
5. 기존 절차와 새 절차의 이중 운영 기간을 정한다.
6. 기존 절차의 종료·유지·복구 조건을 결정한다.
7. 줄어든 업무 시간을 어디에 쓰고 달라진 역할을 어떻게 조정할지 합의한다.

## 실제 사용을 확인할 항목

| 지표 | 질문 |
|---|---|
| 접근 | 필요한 사람이 실제로 사용할 수 있는가 |
| 반복 사용 | 같은 업무에서 다시 선택하는가 |
| 수정 부담 | 결과를 고치는 시간이 줄었는가 |
| 완료 | 새 흐름으로 업무 결과까지 도달하는가 |
| 신뢰 | 근거와 실패 상태를 이해하고 판단하는가 |
| 업무 영향 | 시간·품질·위험·사업 결과가 바뀌는가 |

## 역할별 검수와 인수인계

| 검수 역할 | 직접 확인할 것 | 남길 기록 |
|---|---|---|
| 관리자·업무 책임자 | 목표, 허용 위험, 총비용, 확대·유지·중단 조건 | 결정과 근거, 예외 승인과 기한 |
| 실제 사용자 | 정상·예외 업무의 완료, 수정 부담, 필요한 맥락의 누락 | 수행 결과, 수정 이유, 사용하지 않는 이유 |
| 운영자 | 권한 회수, 중단, 복구, 수동 대체, 문의 처리 | 구현자 도움 없이 수행한 기록과 미해결 항목 |

관리자의 만족을 실제 사용자의 검수로 대신하지 않는다. 역할별 판단이 다르면 평균 점수로 합치지 않고 차이와 해결할 책임자를 남긴다. 한 사람이 여러 역할을 맡았는지도 밝힌다.

줄어든 시간을 검수·코칭·고객 지원 등 어디에 쓸지 합의하고 새 업무의 담당자와 처리 여력을 확인한다. 예외가 모두 AX 엔지니어에게 돌아오거나 사람이 맡아야 할 맥락을 결과에서 빠뜨리면 절차와 역할을 다시 정한다. 인수인계에는 담당자, 대체 담당자, 문의 경로, 미해결 예외, 다음 검토일이 있어야 한다.

검수 뒤 모델·도구·정책이나 업무 절차를 바꾸면 영향을 받는 역할이 다시 확인한다. 처음 배포할 때 받은 검수를 이후 변경에도 계속 적용하지 않는다.

## 산출물

- 사용자 검수 기록
- 교육·지원 자료
- 책임 배분표
- 현업 적용·업무 결과 검토
- 기존 절차 종료 또는 유지 결정

## 통과 기준

- 구현에 참여하지 않은 운영자도 핵심 흐름을 수행할 수 있다.
- 사용하지 않는 이유가 기능·신뢰·교육·절차 중 하나로 구분된다.
- AX Engineer가 모든 일상 운영 요청을 직접 처리하지 않는다.
- 기존 절차의 상태와 최종 책임자를 확인할 수 있다.
- 사용 현황과 업무 결과를 별도로 확인한다.

## 중단 신호

- 사용자를 교육하지 않고 저항으로 해석한다.
- 로그인 수와 생성 건수만 성과로 보고한다.
- 공식 절차는 그대로인데 새 도구 사용만 권장한다.
- 운영 인수인계 전에 개발 인력이 빠진다.
