# 4. 데이터와 업무 맥락

## 목적

AI가 사용할 정보의 출처, 의미, 최신성, 권한을 정한다. 업무 결과가 어떤 원본과 처리 과정을 거쳤는지도 추적할 수 있어야 한다.

## 정보 구분

| 종류 | 예시 | 운영 원칙 |
|---|---|---|
| 원본 데이터 | 주문, 계약, 고객 문의, 재고 | 원본 시스템과 소유자 유지 |
| 가공 데이터 | 정제·통합·분류 결과 | 변환 규칙과 버전 기록 |
| 문서 지식 | 정책, 매뉴얼, 회의록 | 적용 범위와 최신성 표시 |
| 업무 상태 | 승인 대기, 처리 중, 완료 | 실시간 원본 시스템에서 확인 |
| AI 결과 | 분류, 요약, 초안, 제안 | 입력·모델·평가·승인을 함께 기록 |
| 실행 결과 | 생성된 작업, 변경된 상태 | 감사 식별자와 되돌림 정보 기록 |
| 작업 컨텍스트 | 실행 지시, 현재 제약, 미완료 작업 | 출처와 버전을 남기고 압축 뒤에도 제약을 확인 |
| 장기 메모리 | 이전 작업의 요약, 재사용할 지식 | 목적·소유자·보유 기간을 정하고 정정·삭제 반영 |

## 컨텍스트를 줄이거나 다시 불러올 때

요약에서 승인 범위, 금지 행동, 미완료 작업이 빠지면 실행이 달라질 수 있다. 이 정보를 확인할 원본 참조를 남기고 압축 전후 같은 사례를 비교한다. 저장된 승인이나 주문 상태는 실행 직전에 다시 조회한다. 삭제한 기억이 검색 인덱스나 요약에서 계속 복원되지 않는지도 시험한다.

컨텍스트 압축과 구조화 메모는 2025년부터 공개된 접근이다. [Anthropic 기술 문서](https://www.anthropic.com/research/effective-context-engineering-for-ai-agents) (발행일 2025-09-29, 확인일 2026-10-26)를 참고하되 실습에서는 [LLM 기초의 검증 기준](../technical-foundations/llm-foundations.md#컨텍스트-선택과-압축)을 적용한다.

## 주요 작업

1. 최신 상태를 확인할 원본 시스템과 데이터 소유자를 찾는다.
2. 필드·식별자·단위·시간대·결측 의미를 데이터 계약으로 정한다.
3. 업무 용어와 지표의 정의를 맞춘다.
4. 원본·가공·AI 결과·실행 결과를 분리한다.
5. 최신성, 보존 기간, 접근 권한, 삭제 기준을 정한다.
6. 누락·중복·오래된 값·충돌을 평가 데이터에 포함한다.
7. 컨텍스트 선택·압축·메모리 갱신 정책을 버전으로 관리하고 제약 보존을 시험한다.

## 산출물

- 데이터 계약
- 원본 시스템과 소유자
- 용어집과 지표 정의
- 데이터 계보
- 품질·최신성·권한 규칙
- 컨텍스트·메모리 정책과 압축·정정·삭제 시험 기록

## 통과 기준

- 중요한 결과가 어떤 원본에서 왔는지 추적할 수 있다.
- 실시간 상태와 문서 검색의 차이가 설계에 반영돼 있다.
- 누락과 표본 편향을 표현할 수 있다.
- 데이터 소유자와 접근 승인자가 확인됐다.
- AI 결과를 원본 사실로 덮어쓰지 않는다.
- 압축 뒤에도 승인 범위·금지 행동·미완료 작업과 원본 참조가 남는다.
- 정정·삭제한 정보가 후속 조회와 실행에 반영되며 실행 전 최신 상태를 확인한다.

## 중단 신호

- 원본 시스템을 알 수 없는데 복제 데이터로 결정을 자동화한다.
- 같은 용어가 팀마다 다른 뜻인데 정의를 미룬다.
- 수집 범위와 누락을 숨긴 채 정확도를 계산한다.
- 필요한 데이터 접근 권한을 얻을 현실적인 경로가 없다.
