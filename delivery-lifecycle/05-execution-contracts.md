# 5. 실행 규칙과 통제

## 목적

AI가 업무에 참여할 때 지켜야 할 입력·출력·평가·권한·승인·기록·복구 규칙을 한 문서에 정리한다. 이 저장소에서는 이를 `업무 실행 규칙`이라고 부른다.

## 최소 실행 규칙

| 영역 | 확인할 내용 |
|---|---|
| 목적 | 누구의 어떤 업무 결과를 바꾸는가 |
| 입력 | 필수 필드, 출처, 최신성, 누락 처리 |
| 출력 | 스키마, 형식, 품질 기준, 근거 |
| 평가 | 정상·경계·실패·공격 사례, 반복 횟수, 원본 최종 상태와 판정 기준 |
| 권한 | 읽기·제안·생성·변경·외부 전송 범위 |
| 승인 | 승인자, 승인 대상·인자·버전, 만료와 위임 |
| 신원 | 사람·에이전트·서비스 계정의 소유자, 자격증명 만료·회수 |
| 정책 장애 | 정책 서버가 응답하지 않을 때의 차단·수동 처리·복구 |
| 기록 | 업무·상위 실행·하위 에이전트·외부 결과 ID와 구성 버전 |
| 장기 작업 | 추가 입력, 승인 대기, 재접속, 취소 요청과 실제 중단 확인 |
| 복구 | 중단·재시도·되돌림·수동 처리 |
| 비용 | 건별·기간별 한도, 검수 통과 완료 업무당 총비용, 한도 초과 시 조치 |
| 책임 | 업무·데이터·기술·보안 책임자 |

## 자율성 수준

| 수준 | AI 역할 | 실행 |
|---|---|---|
| A0 | 탐색·초안 없음 | 사람이 전부 수행 |
| A1 | 검색·요약·초안 | 사람이 판단·실행 |
| A2 | 선택지와 근거 제안 | 사람이 선택·실행 |
| A3 | 실행안 생성 | 담당자 승인 후 시스템 실행 |
| A4 | 제한된 자동 실행 | 정책·감시·복구 범위 안에서 실행 |

자율성은 모델 성능만으로 높이지 않는다. 피해 규모, 탐지 가능성, 되돌림 가능성, 책임 구조를 함께 본다.

## 승인과 재개 조건

승인은 대상, 인자, 실행 범위와 연결해 저장한다. 대기 중 데이터나 실행안이 바뀌거나 승인·자격증명이 만료되면 재개 전에 다시 확인한다. 하위 에이전트에 위임해도 승인 범위는 그대로다.

취소 요청을 받은 시점과 작업이 실제로 멈춘 시점을 구분한다. 이미 외부 변경이 발생했다면 원본 결과를 대사하고 복구하거나 담당자에게 넘긴다. MCP Tasks의 취소도 즉시 중단을 보장하지 않는다. [공식 Tasks 안내](https://modelcontextprotocol.io/extensions/tasks/overview) (2026-07-28에 공식 확장으로 이동, 확인일 2026-10-26). 구체적인 상태표는 [에이전트 시스템](../technical-foundations/agent-systems.md#오래-걸리는-작업과-재개)을 참고한다.

## 주요 작업

1. [업무 실행 규칙 템플릿](../toolkit/execution-contract.md)을 작성한다.
2. 정상·경계·실패 사례마다 적용할 평가 기준을 정한다.
3. 역할별 권한과 승인 만료를 정한다.
4. 실행과 결과를 같은 식별자로 기록한다.
5. 실패 유형별 중단·재시도·복구를 정한다.
6. 실행 규칙의 버전과 이전 버전 지원 범위를 정한다.
7. 모델·API·SDK·프롬프트·도구·harness·컨텍스트 정책·평가 세트 버전을 기록한다.
8. 정책 장애, 승인 만료, 재접속, 취소 뒤 외부 결과를 시험한다.

## 산출물

- 업무 실행 규칙
- 평가 데이터와 판정 기준
- 역할별 권한·승인표
- 감사 이벤트 스키마
- 실패·복구 절차
- 버전·호환성 정책

## 통과 기준

- AI가 할 수 있는 일과 할 수 없는 일이 모두 적혀 있다.
- 승인자가 무엇을 보고 판단하는지 알 수 있다.
- 성공으로 기록한 실행도 실제 업무 결과를 확인하고 검토 기록을 남긴다.
- 같은 외부 시스템 작업이 중복 실행되지 않는다.
- 실패를 재현하고 수동으로 복구할 수 있다.
- 승인 대기·재접속 뒤에도 대상과 권한을 다시 확인하고 중복 실행을 막는다.
- 정책 서버 장애가 금지된 쓰기를 허용하지 않는다.
- 취소 응답과 실제 중단을 구별하고 부분 성공을 대사한다.
- 완료 업무 수와 실패·검수·재작업을 포함한 비용을 같은 범위에서 설명할 수 있다.

## 중단 신호

- 프롬프트만으로 업무 규칙을 대신한다.
- 승인 여부만 기록하고 승인 근거를 남기지 않는다.
- 실행 권한은 있지만 되돌리거나 중단할 권한이 없다.
- 모델·API·SDK·도구·harness·컨텍스트 정책 변경이 평가 없이 운영에 반영된다.
