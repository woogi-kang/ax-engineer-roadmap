# AX 엔지니어의 협업 역할 안내

이 로드맵의 주 독자는 AX 엔지니어지만, 한 업무를 AX로 전환하려면 현업·리더·데이터·보안·운영 담당자와 업무 목표, 승인, 데이터 사용, 배포, 중단 기준을 함께 정해야 한다. 여기서는 AX 엔지니어의 실행 경로와 세 협업 역할의 책임을 나눠 설명한다.

## 모든 역할이 함께 정할 항목

역할은 달라도 다음 사항은 함께 판단한다.

1. 업무 문제와 AI 문제를 구분한다.
2. 현재 흐름, 대기, 예외, 인수인계를 확인한다.
3. 제거·단순화·표준화·담당자 판단·AI 보조·자동 실행을 구분한다.
4. 원본 데이터, 출처, 누락, 용어, 소유자를 확인한다.
5. 정상·경계·실패 결과와 판정자를 정한다.
6. 금지 행동, 승인, 중단, 복구, 수동 대체를 설계한다.
7. 사용량과 업무 결과를 따로 측정한다.
8. 결정·변경·승인·실패 기록을 남긴다.

답하기 어려운 항목이 많다면 [시작점 안내](../start-here/README.md)와 [AX 업무 전환 8단계](../delivery-lifecycle/README.md)를 먼저 본다.

## 검수 역할을 나누는 방법

구현자는 실행 기록과 실패를 제출한다. 실제 사용자는 업무 품질과 수정 부담을 확인하고 운영자는 중단·복구와 인수인계를 직접 수행한다. 관리자·업무 책임자는 가치, 총비용, 허용 위험을 검토해 확대·유지·수정·중단을 결정한다.

한 사람이 여러 역할을 맡으면 검수 기록에 이를 표시한다. 구현자 외 검토자가 새 시나리오의 결과를 판정해야 하며 검토자가 없으면 자기 점검만으로 통과 처리하지 않는다. 역할별 의견 차이와 미해결 항목도 다음 담당자에게 넘긴다.

## 함께 일하는 방식

```mermaid
flowchart LR
    B["현업 실무자<br/>문제·검수·실제 사용"] --> X["함께 정한 실행 규칙"]
    A["AX 엔지니어<br/>구현·평가·배포"] --> X
    L["리더·의사결정자<br/>우선순위·책임"] --> X
    D["데이터·보안·운영 담당자<br/>데이터·통제·복구"] --> X
    X --> E["운영 기록과 다음 결정"]
```

함께 정한 실행 규칙에는 최소한 목표, 입력·출력, 원본 데이터, 권한, 평가, 승인, 중단, 복구, 기록, 책임자를 넣는다. [업무 실행 규칙 템플릿](../toolkit/execution-contract.md)을 출발점으로 사용할 수 있다.

## 역할 안내를 활용하는 방법

추천 읽기 순서는 각 협업자의 관심 영역을 안내하며 P1~P4 실습의 통과 순서를 바꾸지 않는다.

각 문서는 별도의 직무 로드맵이 아니다. AX 엔지니어는 협업 상대가 무엇을 결정하는지 확인하고, 협업자는 자신의 책임 범위에서 필요한 기준과 결과물을 준비한다. 모든 역할이 코드를 만들 필요는 없지만 배포·운영·중단 결정에 필요한 근거는 각 책임자가 제공해야 한다.
