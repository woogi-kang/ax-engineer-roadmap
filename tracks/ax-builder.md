# AX 엔지니어 실행 경로

## 대상

업무 흐름을 소프트웨어, 데이터, LLM, 도구 호출과 연결해 배포·운영하려는 AX 엔지니어를 위한 실행 경로다. 기존 백엔드·프론트엔드·데이터·자동화 경험은 도움이 되지만 필수 출발점은 아니다.

## 목표

작동하는 데모가 아니라 다른 사람이 검수하고, 운영하고, 중단하고, 이어서 개선할 수 있는 업무 시스템을 만든다.

## 구현 전 선택 순서

복잡한 에이전트를 기본값으로 두지 않는다.

```text
규칙 기반 처리
→ 검색·분류
→ 초안·제안
→ 담당자 승인 후 실행
→ 범위가 제한된 자동 실행
→ 앞 방식으로 풀리지 않을 때만 Agent Loop
```

각 단계에서 품질, 비용, 지연, 권한, 복구 가능성을 비교한다. 더 단순한 방식이 성공 기준을 충족하면 그 방식을 유지한다.

## 1. 소프트웨어와 API

- HTTP, REST API, 인증·인가, 웹훅, 배치, 큐를 이해한다.
- 스키마, 트랜잭션, 재시도, 중복 실행 방지와 멱등성(idempotency)을 업무 영향과 연결한다.
- 시크릿과 환경 설정을 코드에서 분리한다.
- 단위·통합·종단 간 테스트와 배포 파이프라인을 만든다.

상세: [소프트웨어와 API](../technical-foundations/software-and-api.md)

## 2. LLM과 에이전트 시스템

- 토큰, 컨텍스트, 생성 제어, 비용, 모델 선택 조건을 안다.
- 구조화 출력, 검색, 도구 호출을 독립적으로 평가한다.
- Agent Loop와 Planner–Executor 같은 구조가 필요한 조건을 설명한다.
- 메모리를 사실 저장소와 구분하고 삭제·갱신 정책을 둔다.

상세: [LLM 기초](../technical-foundations/llm-foundations.md), [에이전트 시스템](../technical-foundations/agent-systems.md)

## 3. 도구와 통합

- 읽기와 쓰기 도구를 나누고 최소 권한을 적용한다.
- 모델 출력과 실제 실행 사이에 스키마 검증·정책·승인을 둔다.
- MCP를 연결 표준으로 이해하되 인증·업무 승인·감사를 대신한다고 보지 않는다.
- 테스트 환경에서 외부 부작용과 중복 실행을 재현한다.

상세: [도구 호출과 MCP](../technical-foundations/tools-and-mcp.md)

## 4. 평가와 안전

- 정상·경계·실패·공격 사례를 평가 세트로 만든다.
- 검색, 생성, 도구 선택, 최종 업무 결과를 분리해 평가한다.
- 변경 전후 회귀 평가와 담당자 검토를 반복해서 실행한다.
- 금지 행동과 승인 우회가 실제로 차단되는지 시험한다.

상세: [평가와 테스트](../technical-foundations/evaluation-and-testing.md), [보안과 개인정보](../technical-foundations/security-and-privacy.md)

## 5. 운영과 인수인계

- 실행 식별자로 입력, 모델·프롬프트·도구 버전, 승인, 외부 실행, 오류를 추적한다.
- SLO, 비용 한도, 경보, 중단, 롤백, 수동 대체를 설계한다.
- 운영자가 문서와 실행 기록만으로 대표 장애를 진단하고 복구할 수 있게 한다.
- 개인 계정·로컬 환경·암묵적 지식 의존을 제거한다.

상세: [운영과 관측성](../technical-foundations/production-operations.md)

## 남길 결과물

- 실행 가능한 코드와 재현 절차
- 입력·출력·API·이벤트 계약
- 평가 데이터, 판정 기준, 회귀 결과
- 위협 모델과 권한표
- 로그·메트릭·트레이스 또는 동등한 실행 기록
- 배포, 중단, 복구, 수동 대체 기록
- 운영자·개발자용 인수인계 문서

## 협업 경계

AX 엔지니어가 혼자 정하지 않는 항목:

- 업무 목표와 완료 기준
- 데이터 사용의 적법성과 소유권
- 결과를 승인할 권한
- 위험 허용 수준과 기존 절차 종료
- 운영 장애의 사업 우선순위

각 항목은 [현업 실무자](business-practitioner.md), [리더·의사결정자](leader-and-governance.md), [데이터·보안·운영 담당자](data-security-operations.md)와 함께 [업무 실행 규칙](../toolkit/execution-contract.md)을 작성하면서 합의한다.

## 자주 발생하는 실패

- 프레임워크를 고른 뒤 문제를 그 구조에 맞춘다.
- 모델 출력이 좋아졌다는 이유로 실행 권한을 확대한다.
- 자동 재시도로 외부 작업을 중복 실행한다.
- 대화 기록만 남기고 버전·승인·외부 실행을 추적하지 못한다.
- 첫 프로젝트 코드를 공통 플랫폼으로 추상화한다.
