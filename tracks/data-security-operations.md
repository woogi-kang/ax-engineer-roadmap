# 데이터·보안·운영 트랙

## 대상

데이터 소유, 개인정보, 정보보안, 플랫폼 운영, SRE, 감사, 장애 대응 책임을 맡는 사람을 위한 트랙이다.

## 목표

검토 의견만 전달하는 후반 승인자가 아니라, 업무 발견 단계부터 데이터 사용·권한·관측·복구 조건을 함께 설계한다.

## 1. 데이터와 의미

확인할 항목:

- 최신 사실을 가진 원본 시스템과 데이터 소유자
- 수집 목적, 출처, 적법 근거, 보유·삭제 기준
- 정형·비정형 데이터의 누락, 중복, 최신성, 표본 편향
- 업무 용어와 지표 정의
- 원본, 파생, 모델 입력, 모델 출력, 실행 결과의 계보

벡터 저장소나 대화 기록을 회사의 사실 저장소로 취급하지 않는다. 검색용 복제본과 원본의 갱신·삭제 관계를 적는다.

증거:

- 데이터·소유자·계보 지도
- 데이터 분류와 처리 목적
- 용어집과 품질 보고서
- 보유·삭제·정정 절차

## 2. 접근 권한과 실행 통제

사람, 서비스 계정, 모델이 사용하는 도구의 권한을 나눈다.

- 읽기, 제안, 승인 요청, 쓰기, 삭제 권한을 분리한다.
- 운영과 테스트 계정을 분리한다.
- 고위험 실행에는 업무 승인과 기술 통제를 함께 둔다.
- 권한 변경과 승인 우회를 감사할 수 있게 기록한다.
- 공급자와 외부 서비스의 데이터 접근 범위를 확인한다.

증거:

- 역할·서비스 계정 권한표
- 승인과 위임 기준
- 권한 변경·회수 기록

## 3. 개인정보와 보안 위협

수명주기 전체에서 확인한다.

- 목적 적합성과 최소 수집
- 데이터 출처 검증과 가명·익명 처리
- 프롬프트 공격, 데이터 유출, 도구 오용, 권한 상승
- 입력·출력 필터, 격리, 허용 정책
- 배포 전 시험, 취약점 점검, 정보주체 권리 지원
- 내부 관리와 보고 책임

법률 적용을 일반화하지 않는다. 개인정보 보호책임자, 법무, 보안 책임자가 현재 업무·대상·데이터·지역을 기준으로 확인한다.

상세: [보안과 개인정보](../technical-foundations/security-and-privacy.md)

## 4. 관측과 감사

대화 전문을 무조건 저장하지 않는다. 원인을 추적할 최소 정보와 저장 금지 정보를 함께 정한다.

실행 식별자로 연결할 항목:

- 사용자·서비스 역할
- 입력 참조와 데이터 버전
- 모델·프롬프트·도구 버전
- 정책 판정과 승인
- 외부 실행과 결과
- 오류, 재시도, 중단, 복구
- 비용과 지연

상세: [운영과 관측성](../technical-foundations/production-operations.md)

## 5. 장애와 복구

대표 실패를 실제로 주입한다.

- 원본 시스템 지연·오류
- 오래되거나 누락된 데이터
- 잘못된 도구 선택
- 권한 거부
- 모델 품질 저하
- 비용·반복 한도 초과
- 외부 작업의 부분 성공과 중복 실행

각 실패를 자동 재시도, 사람 인계, 즉시 중단 중 하나로 분류한다. 수동 대체에는 담당자, 입력, 처리 기한, 복구 후 대사 절차를 넣는다.

증거:

- 위협 모델
- 장애 분류와 대응표
- 중단·복구·수동 대체 훈련 기록
- 사고 보고와 개선 결정

## 6. 운영 인수인계

구현자가 없는 상태에서 운영자가 다음을 수행하게 한다.

- 현재 상태와 영향 범위를 확인한다.
- 대표 오류의 실행 이력을 추적한다.
- 필요한 경우 자동 실행을 중단한다.
- 수동 절차로 전환한다.
- 복구 후 누락·중복 결과를 대사한다.

## 자주 발생하는 실패

- 보안 검토를 출시 직전 체크리스트로만 수행한다.
- 모든 대화와 문서를 장기간 저장하는 것이 감사라고 생각한다.
- 사람 계정의 넓은 권한을 에이전트 서비스 계정에 그대로 준다.
- 연결 프로토콜이 인증·인가와 업무 승인을 해결한다고 본다.
- 자동 재시도와 중복 방지를 따로 시험하지 않는다.
- “문제가 생기면 사람이 처리”한다고만 적고 복구 훈련을 하지 않는다.
