# 리더·의사결정자 협업 안내

## 대상

AX 포트폴리오, 예산, 조직 구조, 조달, 위험 허용, 업무 책임을 결정하는 리더와 프로그램 운영자를 위한 협업 안내다.

## 목표

도구 구매나 전사 선언을 성과로 보지 않는다. 가치 있는 업무를 안전하게 배포하고, 실제 운영 기록을 바탕으로 확대·수정·중단할 수 있는 조직 능력을 만든다.

## 1. 포트폴리오 우선순위

후보를 기대 효과만으로 정렬하지 않는다. 가치, 빈도, 사용자, 기준선, 데이터 준비, 위험, 복구 가능성, 담당자, 현업 정착 난이도를 함께 본다.

필요한 결정:

- 지금 시작할 업무와 보류할 업무
- AI 없이 제거·단순화할 업무
- 파일럿 예산과 검증 기간
- 확대, 유지, 수정, 중단 기준

결과물:

- [업무 후보 평가표](../toolkit/use-case-scorecard.md)
- 포트폴리오 결정 기록
- 후보별 범위·비목표·중단 조건

## 2. 책임과 승인 구조

위원회 이름보다 실제 의사결정권을 적는다.

```text
업무 목표와 결과 승인
데이터 사용 승인
배포 승인
외부 실행 권한
장애 시 중단 권한
기존 절차 종료
공급자 계약과 종료
```

한 항목에 최종 책임자가 둘이면 충돌 해결 방식을 적는다. 개인 이름이 아니라 역할과 대체 책임자를 기록한다.

결과물:

- 책임 배분표
- 승인·위임 기준
- 긴급 중단과 보고 경로

## 3. 투자와 운영 기준

파일럿 비용에는 모델 사용료만 넣지 않는다. 데이터 정리, 통합, 평가, 보안 검토, 사용자 검수, 교육, 지원, 운영, 공급자 교체 비용을 포함한다.

업무 결과 지표와 운영 지표를 나눈다.

- 업무 결과: 완료 시간, 오류·재작업, 고객·직원 영향, 기회 비용
- 운영: 품질, 지연, 비용, 장애, 승인 대기, 수동 대체
- 현업 정착: 공식 절차 사용률, 수정 부담, 지원 요청, 기존 절차 종료

## 4. 조달과 공급자 종료 계획

구매 전에 다음을 확인한다.

- 조직 계정과 관리자 권한의 소유자
- 입력 데이터의 사용·보관·학습 조건
- 데이터 내보내기 형식과 삭제 확인 기록
- 로그와 감사 기록 접근
- 모델·공급자 교체 가능성
- 계약 종료 시 업무 복귀와 데이터 처리
- 하도급·국외 이전·지역 저장 등 법무 검토 항목

법률·규제 적용 여부는 현재 공식 자료와 담당 전문가에게 확인한다.

## 5. 현업 정착과 역할 전환

교육 횟수와 좌석 수보다 공식 업무가 바뀌었는지 본다.

- 현장 사용자가 설계·검수에 참여하는가?
- 부서·지역별 지원 책임자가 있는가?
- 새 SOP와 KPI가 승인됐는가?
- 이중 운영 기간과 기존 절차 종료 조건이 있는가?
- AX팀 없이도 일반 예외를 처리할 수 있는가?

## 6. 공통 기반을 만드는 시점

첫 성공 사례를 곧바로 플랫폼 요구사항으로 만들지 않는다. 두 번째 업무에서 실제로 재사용된 계약과 구성 요소만 후보로 올린다.

공통화할 수 있는 항목:

- 업무·실행 식별자
- 입력·출력 스키마와 버전
- 평가 실행과 결과 기록
- 승인·권한·감사 이벤트
- 중단·복구·수동 대체
- 비용·품질·실제 사용 상태

팀마다 달라도 되는 항목:

- 화면과 사용자 경험
- 도메인별 용어와 규칙
- 모델·프레임워크 선택
- 원본 시스템 연결 방식

## 남길 결과물

- AX 포트폴리오와 결정 이력
- 투자·중단 기준
- 역할별 책임과 승인표
- 조달·공급자 종료 체크리스트
- 파일럿 운영 리뷰
- SOP·KPI·역할 변경 승인
- 두 번째 업무 재사용 비교

## 자주 발생하는 실패

- 경영진 관심이 큰 아이디어를 검증 없이 첫 업무로 정한다.
- 중앙팀이 모든 구현·승인·지원의 영구 병목이 된다.
- “전사 플랫폼”을 먼저 사고 업무를 나중에 찾는다.
- 법무·보안 검토를 배포 직전 승인 절차로만 둔다.
- 파일럿의 좋은 데모를 전사 성과로 확대 해석한다.
- 종료 계획 없이 특정 공급자 계정과 데이터 형식에 묶인다.
