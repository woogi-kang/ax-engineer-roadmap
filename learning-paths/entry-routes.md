# 경험에 맞는 AX 진입 경로

이 문서는 현재 가진 경험을 첫 실습의 범위와 연결한다. 경력 연수로 Foundation·Builder·Operator·Lead를 배정하지 않는다. [숙련도](../roadmap/proficiency-levels.md)는 맡은 책임과 검증한 결과로 판단하며 아래 경로는 채용 자격이나 취업 보장을 뜻하지 않는다.

[공개 역할 검토](../research/ax-engineer-role-review.md)는 내부 업무 구현, 공통 기반, 현업 지원처럼 서로 다른 책임을 보여 준다. 이 문서의 경로는 그 차이를 학습에 적용한 제안이다. 경력 초반 채용이 늘었다거나 모든 공고가 같은 준비를 요구한다는 주장은 하지 않는다.

## 시작 전에 확인할 것

이번에 맡을 역할을 [역할 선택 안내](../start-here/persona-selector.md)에서 정하고 [조직 준비도](../start-here/organization-readiness.md)를 확인한다. 다음 항목은 경로와 무관하게 기록한다.

- 내가 직접 구현할 부분과 업무·보안·운영 담당자가 판단할 부분
- 사용할 데이터의 출처와 허용 범위, 테스트 계정과 실행 권한
- 구현에 참여하지 않고 결과를 판정할 사람
- 실패하면 멈출 조건과 원래 업무로 돌아갈 방법

첫 P1 실습에는 공개·합성 데이터만 사용하며 외부 업무 시스템을 변경하지 않는다. 여기서 외부 실행 금지는 고객 대상 발송·게시와 업무 시스템 쓰기를 뜻한다. 허용된 로컬 모델이나 모델 API의 입력 처리는 [P1의 데이터·계정·비용 조건](../projects/01-safe-assistant.md)에 따라 별도로 확인한다. 조직 데이터나 운영 권한이 없어도 시뮬레이션을 할 수 있지만 실제 사용자 도입이나 조직 성과를 주장하지 않는다. 검토자를 구하지 못하면 자기 점검 결과만 남기고 통과 판정은 보류한다.

## 내 경험과 가까운 경로

| 현재 경험 | 먼저 확인할 공백 | 시작할 실습 | 첫 결과물 예시 |
|---|---|---|---|
| 개발 경력이 짧거나 처음 구현한다 | 입력·출력, 코드 실행, 오류 읽기와 평가 재현 | P1부터 작은 보조 기능 구현 | 공개 매뉴얼 답변과 출처·거절 결과 |
| 웹·백엔드·데이터·자동화 개발 경험이 있다 | 업무 기준선, AI 평가, 승인과 운영 인수인계 | P1 검수 후 P2, 이어 P3 통합 | 합성 요청 분류 서비스와 평가 기록 |
| 업무 도메인을 잘 알지만 개발 경험은 제한적이다 | 협업자로 맡을 판단과 엔지니어로 직접 맡을 구현의 차이 | P1·P2에 협업하거나 P1 구현부터 전환 준비 | 합성 정산 요청의 누락 증빙·검토 근거표 |

모든 경로의 시작은 P1이다. 기존 코드와 경험을 재사용할 수는 있지만 P1~P4 통과 기준을 면제하지 않는다. P4는 실전 또는 공개 시뮬레이션의 조건과 판정명을 따르며 두 경로 모두 실행·복구·독립 검수 기록이 필요하다. 이미 수행한 실습이 있으면 해당 결과가 이번 데이터·권한·버전·업무 조건에서도 유효한지 검토자가 다시 확인한다.

## 1. 개발 경력이 짧거나 처음 구현하는 사람

| 항목 | 실행할 내용 |
|---|---|
| 시작 전 확인 | 입력을 읽어 정해진 형식으로 출력하고 오류 메시지를 찾아 수정할 수 있는지 확인한다. 어렵다면 파일 읽기, 함수 작성과 테스트 실행을 별도 선행학습으로 익힌다. [소프트웨어와 API](../technical-foundations/software-and-api.md)는 그 뒤에 필요한 통합·권한·실패 처리 기준을 확인하는 문서다. |
| 데이터와 권한 | 사용 가능한 공개 매뉴얼 하나를 골라 출처와 버전을 남긴다. 실제 고객·직원 정보, 업무 시스템 계정과 발송·변경 도구는 사용하지 않는다. |
| 작은 첫 결과물 | 질문에 매뉴얼의 근거 구간을 붙여 답하거나 답할 수 없다고 표시하는 P1 보조 기능을 만든다. 규칙 기반 결과와 비교하고 실행 방법, 비용·지연, 실패 기록을 함께 남긴다. |
| 검수와 중단 | [P1](../projects/01-safe-assistant.md)의 정상·경계·실패 평가를 최소 20개 준비한다. 다른 사람이 새 입력으로 출처와 거절을 확인한다. 비공개 입력, 반복되는 근거 없는 답, 비용·지연 한도 미확인이 있으면 멈춘다. |
| 다음 단계 | P1 통과 후 승인자가 변경 전후와 근거를 판단할 수 있는 P2를 만든다. P2에서는 승인 결과를 모의 실행으로 남긴다. 실제 쓰기 시험은 P3의 격리 환경에서 진행하고 운영 쓰기는 P4 실전 조건과 별도 승인을 갖춘 뒤 다룬다. |

코드 작성 도구의 도움을 받아도 본인이 입력, 출력과 실패 이유를 설명하고 같은 평가를 다시 실행할 수 있어야 한다. 문서나 표로 판단을 연습했다면 그 범위를 남기고 실행 가능한 구현을 검증했다고 표시하지 않는다.

## 2. 기존 개발 경험으로 AX 업무를 맡으려는 사람

| 항목 | 실행할 내용 |
|---|---|
| 시작 전 확인 | API나 배포 경험과 별개로 업무의 현재 처리 시간, 오류·수정 부담, 최종 승인자를 설명할 수 있는지 확인한다. AI 출력 평가와 업무 완료 판정이 다르면 평가 기준을 나눈다. |
| 데이터와 권한 | P1은 합성 요청과 테스트 입력으로 시작한다. P3에서 연결할 시스템에는 별도 테스트 계정과 최소 권한을 준비한다. 업무 시스템의 운영 자격증명이나 기존 개인 계정을 실습에 가져오지 않는다. |
| 작은 첫 결과물 | 합성 지원 요청을 분류하고 이유와 보류 조건을 반환하는 P1 서비스를 만든다. 기존 서비스 골격을 써도 P1의 최소 20개 평가와 새 입력 검수를 수행한다. |
| 검수와 중단 | 업무 담당자는 분류와 보류 기준을 검수하고 독립 검토자는 실행·실패 기록을 확인한다. 다음 P2·P3에서 승인 우회, 중복 실행이나 부분 성공을 구분하지 못하면 권한을 넓히지 않는다. |
| 다음 단계 | P1 통과 후 P2에서 요청 ID·승인 대상 버전·취소 상태를 확인하고 P3에서 두 테스트 시스템의 통합과 복구를 시험한다. 실제 운영자와 사용자, 배포·중단 승인이 준비됐을 때 P4 실전을 검토하고 조직 조건이 없으면 P4 공개 시뮬레이션 조건을 확인한다. |

익숙한 프레임워크를 새 업무의 정답으로 삼지 않는다. 업무를 단순화하거나 기존 기능을 쓰는 선택도 비교한다. 운영 경험이 있어도 이번 업무의 평가, 승인과 인수인계 근거가 필요하다.

## 3. 도메인 경험을 가진 사람

도메인 전문가는 업무 판단을 맡는 협업자로 참여할 수 있다. 엔지니어로 전환하려면 구현과 실패 처리도 직접 맡을 준비를 별도로 한다. 어느 쪽을 선택하든 업무 지식만으로 데이터 사용이나 배포를 승인할 권한이 생기지는 않는다.

| 항목 | 현업 협업자로 참여 | 엔지니어 전환을 준비 |
|---|---|---|
| 시작 전 확인 | 정상 처리와 예외, 검토 근거, 잘못 처리했을 때의 영향을 설명한다. | 왼쪽 항목에 더해 코드 실행·오류 수정·테스트 재현을 확인한다. 부족하면 소프트웨어 기초부터 연습한다. |
| 데이터와 권한 | 실제 사례를 복사하지 않고 공개 규칙과 합성 정산 요청을 만든다. 데이터·승인 책임자는 별도로 지정한다. | 같은 데이터를 사용하고 외부 실행 없는 P1을 만든다. 실제 조직 데이터는 허용 범위를 확인한 뒤 별도 단계에서 다룬다. |
| 작은 첫 결과물 | 누락 증빙, 판단을 보류할 이유, 담당자에게 넘길 조건을 적은 검토표와 정상·경계·실패 평가 입력을 만든다. | 같은 입력으로 누락 증빙과 근거를 반환하는 코드를 만들고 실행 방법과 평가 기록을 남긴다. |
| 검수와 중단 | 구현자는 결과가 기준과 어떻게 연결되는지 설명하고 다른 업무 검토자가 판정 기준을 확인한다. 원문 규칙이 상충하거나 승인자가 없으면 처리안을 확정하지 않는다. | P1의 최소 20개 평가와 새 입력 검수를 받는다. 출처 없는 판단, 비공개 입력이나 재현할 수 없는 실패가 있으면 멈춘다. |
| 다음 단계 | P2의 승인 기준·수정 이유·수동 대체 절차를 엔지니어와 검증한다. P3 구현·배포·복구의 담당자는 명시한다. | P1을 통과한 뒤 P2·P3를 순서대로 수행한다. 이후 실제 운영 조건을 갖추면 P4를, 조건이 없으면 운영 시뮬레이션을 진행한다. |

현업 협업자의 검수·SOP 결과는 [현업 실무자 경로](../tracks/business-practitioner.md)의 기여로 기록한다. 그것만으로 엔지니어의 구현·배포 책임을 검증했다고 쓰지 않는다. 전환을 선택했다면 [AX 엔지니어 실행 경로](../tracks/ax-builder.md)에서 본인이 맡을 기술 영역과 도움받을 담당자를 정한다.

## 다음 단계로 넘어갈 때 확인할 근거

| 단계 | 다음 단계에 필요한 근거 |
|---|---|
| [P1 안전한 보조 도구](../projects/01-safe-assistant.md) | 출처·거절·정상·경계·실패 평가와 독립 검수. 외부 실행 없음. |
| [P2 담당자 승인](../projects/02-human-approved-workflow.md) | 승인 대상과 버전, 승인자의 권한, 거절·취소·만료 기록. 승인 우회 차단. |
| [P3 샌드박스 통합](../projects/03-sandbox-integration.md) | 격리된 계정, 중복·부분 성공 처리, 중단·복구와 수동 대체의 실행 기록. |
| [P4 운영 파일럿](../projects/04-production-pilot.md) | 실제 사용자·운영자와 승인된 범위, 운영·비용·업무 지표, 장애 대응과 인수인계. 시뮬레이션은 별도 표시. |

표는 [프로젝트별 통과 기준](../projects/README.md)의 요약이며 이를 대체하지 않는다. 조직 자료나 권한이 부족하면 실전 진행을 보류하고 허용된 테스트 환경에서 P4 시뮬레이션 조건을 충족할 수 있는지 확인한다. 테스트 환경이나 독립 검토자도 없다면 설계만 남기고 P5 실행 검증을 보류한다. P4를 실제 운영으로 통과하지 않은 시뮬레이션 결과를 운영 경력으로 바꾸지 않는다.

이 근거를 확인한 뒤 [12주 실습 경로](12-week-practice.md)에 학습 계획을 연결한다. 12주는 과제를 정리하는 일정이며 숙련도 도달 시점이나 채용을 보장하는 기간이 아니다.
