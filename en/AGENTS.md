# Project working instructions

## Scope and existing changes

Work within the current user request. Preserve uncommitted changes and research evidence, and read current files before editing them. Permission to implement or edit documents does not authorize commits, pushes, or deployment. Build a new website only when separately requested.

## Korean writing

Use the `korean-humanizer` skill whenever adding Korean content or revising Korean sentences. Read the session's registered `SKILL.md` and obtain the full instructions. If the skill cannot be located or read, report that limitation and do not claim the pass is complete.

1. Verify sources and scope, then draft the content. Establish facts, numbers, dates, and implementation status at this stage.
2. Review added or changed Korean text for translationese, inflated claims, abstract wording, and repetitive sentence patterns.
3. Edit only the identified passages. Preserve the plain tone of technical documentation and do not rewrite sound existing prose merely for uniformity.
4. Compare proper names, numbers, dates, quotations, technical abbreviations, and evidence links before and after polishing. Revert edits that alter meaning or claim boundaries.
5. Check that the English edition describes the same responsibilities, procedures, exit criteria, and limitations.

Apply the skill's change-rate limits between the completed substantive draft and its polished version. Do not combine evidence additions with stylistic edits when measuring that rate, or discard needed evidence because an addition is long. Bulk updates to other installed skills or system settings are outside the writing task.

## Evidence and validation

Distinguish publication date, observation period, and verification date. Do not present inaccessible sources, self-reported outcomes, or historical job listings as currently verified facts. Adding practice instructions is different from implementing runnable code; do not raise a case's implementation stage or outcome grade without evidence.

Run the documentation, case, and practice checks relevant to the change. Automation does not establish bilingual semantic parity or factual accuracy, so review the prose separately. Report observed results and remaining limitations.
