# Role Roadmap

This directory describes the responsibilities and proficiency of internal AX Engineers. Continue to the [Collaboration Role Guides](../tracks/README.md) for partner decisions and the [Technical Foundations](../technical-foundations/README.md) for implementation depth.

## Seven axes in this roadmap

The numbers and stages are not one score or a single linear sequence. They ask different questions about the same workflow.

| Axis | Question | Range |
|---|---|---|
| Transformation lifecycle | How far has the workflow progressed? | Eight stages from goals and current flow through redesign, data, controls, deployment, adoption, and scale |
| Competency map | What must the team be able to do? | Eight areas across value, workflow, data, integration, AI, operations, adoption, and organizational learning |
| Project `P1–P5` | What level of execution evidence exists? | Assistance → approval → sandbox → limited operation → second-workflow reuse |
| Autonomy `A0–A4` | How much action authority does AI receive? | Human execution → recommendation → bounded multi-step work → post-approval action → bounded automatic action |
| Evidence stage | What evidence can be published? | Design blueprint → public simulation → anonymized practice → limited pilot → operating evidence |
| Individual proficiency | What responsibility can one person own? | Foundation → Builder → Operator → Lead |
| Organization maturity `M0–M4` | Can the organization repeat the capability across workflows? | Individual experiment → bounded repetition → operable workflow → shared capability → continuous improvement |

A high-risk workflow may remain at `A1` even in an `M4` organization. A case can be documentation-ready and design P1–P5 while still having only `simulation-design` evidence; that does not imply execution or organizational outcomes.

## Reading principles

- Look at the actual responsibility, not the job title.
- Distinguish experience using a technology from experience producing an operable outcome.
- Do not judge proficiency by tenure or number of tools.
- Connect every competency to a verifiable artifact or operating record.
- Non-developers and developers do not need the same coding depth, but each must explain the approval, acceptance, implementation, and operating boundary they own.
