# 월간 채용 공고 수집 기준

매달 국내 AX·AI Agent·FDE 공고를 제목 수준에서 모아 같은 방식으로 기록한다. 책임과 요건을 한영으로 자세히 정리하는 [채용 공고 기록](../hiring-signals.md)은 대표 표본으로 유지하고, 이 디렉터리는 한 달 동안 올라온 공고의 전체 목록을 맡는다.

## 월별 목록

- [2026년 10월](2026-10.md): 2026-09-27~2026-10-27 접수 시작, 잡코리아 138건.

## 수집 범위

- 기간: 실행일을 끝으로 하는 직전 30일 안에 접수가 시작된 공고. 실행일이 2026-11-27이면 2026-10-28부터 2026-11-27까지다.
- 지역: 국내 근무 공고. 해외 근무나 원격 전용 해외 기업 공고는 넣지 않는다.
- 이전 달 목록에 있던 공고는 다시 넣지 않는다. 같은 기업이 새 공고 번호로 다시 올렸다면 넣고 `possible_duplicate_of`로 이전 번호를 적는다.

## 직무 범위

포함한다.

- AX·AI 전환을 담당하는 엔지니어, 개발자, PM, 기획자, 운영 담당자.
- AI Agent·에이전트·Agentic 시스템을 만들거나 운영하는 직무.
- FDE(Forward Deployed Engineer)와 고객 현장에 배치되는 AI 엔지니어.
- 프로젝트 투입형 SI 공고와 프리랜서 공고. 대신 `project-or-freelance` 태그를 붙인다.

제외하고 사유를 남긴다.

- 회사명에만 AX가 들어간 공고(예: SK㈜ AX의 일반 직무).
- 영업, 컨설팅, 교육 강사·교육 운영, 마케팅, 디자인, 회계 직무.
- 직무를 특정하지 않은 공개 채용.
- 업무 자동화와 관계없는 에이전트(게임 NPC 등)나 보안 진단 중심 직무.
- 접수 시작일이 수집 기간보다 앞서는 공고.

경계에 있는 공고는 제외 목록에 사유와 함께 남겨 다음 달에도 같은 판단을 하도록 한다.

## 분류와 상태

- 유형: 제목에 FDE·Forward Deployed·FD 엔지니어가 있으면 `fde`, 그다음 Agent·에이전트·Agentic이 있으면 `ai-agent`, 나머지는 `ax`로 둔다.
- 모집 중(`open`): 마감일이 확인일 이후이거나 상시 채용이고, 마감 표시가 없다.
- 마감(`closed`): 페이지에 마감 표시가 있거나(`closed-notice`) 마감일이 지났다(`deadline-passed`).
- 미확인(`unknown`): 상세 페이지를 읽었지만 상태를 판단할 수 없다. 페이지 자체를 읽지 못한 공고는 목록에 넣지 않고 보류(`held`)로 둔다.
- 공고 페이지가 404를 반환하면 보류 사유를 `removed`로 바꾸고 `url`을 `null`로 둔다. 외부 링크 검사(`npm run check:external`)가 깨진 링크로 실패하지 않게 하기 위해서다.
- 남은 시간 표시는 캐시된 값일 수 있으므로 상태 판단에 쓰지 않는다.
- 태그: `project-or-freelance`(프로젝트 투입·프리랜서), `company-undisclosed`(헤드헌팅 등 기업명 비공개), `training-matching`(교육기관 매칭 공고).

## 플랫폼별 방법

| 플랫폼 | 방법 | 2026-10 결과 |
| --- | --- | --- |
| 잡코리아 | 검색 `https://www.jobkorea.co.kr/Search/?stext=<검색어>&tabType=recruit&Page_No=<n>`, 상세 `https://www.jobkorea.co.kr/Recruit/GI_Read/<번호>` | 수집 |
| 사람인 | 상세 페이지 확인 시도 | 메타데이터만 보여 미수집 |
| 원티드 | 공고 페이지 확인 시도 | 클라이언트 오류로 미수집 |
| 링크드인 | 확인하지 않음 | robots 규칙으로 미수집 |

잡코리아 검색 목록은 관련도순이고 날짜가 없다. 공고 번호는 시간이 지날수록 커지므로 번호로 후보를 먼저 거른다. 2026-10 기준으로 50053000 이상이 2026-09-27 이후 접수 공고였고, 2026-10-27 접수 공고는 약 50250000이었다. 다음 달에는 직전 목록의 마지막 번호(이번에는 50252108) 근처에서 시작 번호를 다시 맞춘다.

검색어는 AX, AX 엔지니어, AX 개발자, AI 전환, AI Agent, AI 에이전트, 에이전트, Agentic, FDE, Forward Deployed다. 사람인·원티드·링크드인이 읽히게 되면 같은 검색어를 쓰고, 다른 플랫폼에서 찾은 공고는 `platform` 값을 바꿔 같은 파일에 넣는다.

## 실행 절차

1. 검색어마다 잡코리아 검색 결과를 넘기며 `번호 | 기업 | 제목`을 모은다. 기간 하한보다 작은 번호만 나오는 페이지가 이어지면 다음 검색어로 넘어간다.
2. 번호로 중복을 지우고, 기간 하한보다 작은 번호와 이전 달 목록에 있는 번호를 뺀다.
3. 제목으로 직무 범위를 판단해 제외 대상과 사유를 정한다.
4. 남은 후보의 상세 페이지에서 접수 시작일, 마감일, 마감 표시, 지원 방법, 고용 형태, 근무지, 경력을 확인한다. 시작일이 기간 밖이면 제외로 옮긴다.
5. `research/hiring-monthly/YYYY-MM.json`을 쓴다. 공고 ID는 `MYYMM-001`부터 플랫폼 번호 순서로 붙인다.
6. `npm run generate:hiring-monthly`로 한국어·영어 목록을 만들고 이 문서의 월별 목록에 링크를 추가한다.
7. `npm run check`와 `npm run test:hiring`을 통과시킨다. 검사는 기간, 상태 규칙, 번호 순서, 중복, 생성 문서의 최신 여부를 본다.
8. PR 본문에 후보 수, 제외 수, 보류 수, 플랫폼 접근 결과를 적는다.

본문까지 읽어 책임과 요건이 드러나는 공고 몇 건은 [채용 공고 기록](../hiring-signals.md)의 상세 표본에 추가할 수 있다. 이 단계는 선택이며 월간 목록과 별도로 검토한다.

## 데이터 필드

| 필드 | 뜻 |
| --- | --- |
| `month`, `window`, `checked_at` | 목록의 달, 접수 시작일 기간, 확인일 |
| `queries`, `platforms` | 사용한 검색어와 플랫폼별 수집 결과 |
| `postings[].role_type` | `ax`, `ai-agent`, `fde` |
| `postings[].start_date`, `start_basis` | 페이지의 접수 시작일. 없으면 `null`과 `id-range` |
| `postings[].deadline` | 마감일 또는 `rolling`(상시) |
| `postings[].status`, `status_basis` | 상태와 판단 근거 |
| `postings[].tags`, `possible_duplicate_of`, `note` | 태그, 중복 가능 공고 번호, 한국어 메모 |
| `held[]`, `excluded[]` | 보류·제외 공고와 사유 코드 |

## 한계

- 수집 플랫폼이 잡코리아뿐이라 다른 플랫폼에만 있는 공고는 빠진다.
- 검색이 관련도순이라 깊은 페이지에 있는 공고를 놓쳤을 수 있다.
- 접수 시작일이 없는 공고는 번호 범위로 기간을 판단했다.
- 건수에는 재게시와 프로젝트 공고가 섞여 있어 고유 채용 수나 시장 증감을 뜻하지 않는다.
