# 개발자 로드맵과 AI Agent 로드맵 검토

> 확인일: 2026-07-26

## 먼저 구분할 것

[`nilbuild/developer-roadmap`](https://github.com/nilbuild/developer-roadmap)은 [`roadmap.sh`](https://roadmap.sh/)를 만드는 공개 저장소다. 둘을 서로 다른 로드맵 두 개로 세어 비교하지 않는다. 이 문서는 저장소의 실제 파일, 기여 규칙, [`AI Agents Roadmap`](https://roadmap.sh/ai-agents)을 함께 읽고 AX Engineer 로드맵에 가져올 구조와 보완할 공백을 정리한다.

## 가져올 구조

### 한눈에 보고 필요한 곳부터 들어간다

roadmap.sh는 전체 경로를 노드로 보여주고, 노드를 누르면 짧은 설명과 학습 자료를 제공한다. 초보자용 경로, 관련 로드맵, 프로젝트, 질문도 따로 연결한다. 독자는 긴 문서를 처음부터 읽지 않아도 자신의 현재 위치와 다음 항목을 찾을 수 있다.

이 저장소는 다음 방식을 가져온다.

- 전체 구조를 먼저 보여 주고 상세 문서로 연결한다.
- 역할과 조직 준비도에 따라 시작점을 달리한다.
- 개념 학습을 실습 프로젝트와 검증 증거에 연결한다.
- 핵심 노드는 짧게 설명하되, 판단·실습·실패 조건은 별도 문서에 남긴다.

### 가장 큰 목록보다 지금 필요한 항목을 고른다

developer-roadmap의 기여 규칙은 가능한 기술을 전부 모으는 것을 목표로 삼지 않는다. 현재 진입자에게 필요한 항목을 선별하고, 각 주제 설명은 한 문단 안팎으로 유지하며, 자료의 유형과 수를 제한한다.

이 원칙은 AX에도 맞는다. 프레임워크 이름을 늘리면 로드맵이 빨리 낡고 선택 기준은 흐려진다. 따라서 이 저장소는 제품명을 핵심 역량으로 두지 않고, 특정 도구는 현재 구현 예시나 출처로만 다룬다.

## AI Agents Roadmap이 잘 다루는 영역

공개 저장소의 [`ai-agents` 콘텐츠 디렉터리](https://github.com/nilbuild/developer-roadmap/tree/master/src/data/roadmaps/ai-agents/content)는 다음 기술 범위를 다룬다.

1. 백엔드 기초, Git·터미널, REST API
2. LLM, 토큰, 컨텍스트 창, 생성 제어, 모델 비용
3. 에이전트와 Agent Loop
4. 프롬프트 작성
5. 도구 호출, 함수 호출, MCP
6. 단기·장기 메모리
7. RAG, ReAct, Planner–Executor, DAG 등 에이전트 구조
8. 직접 구현, 모델 기본 기능, 프레임워크를 이용한 구현
9. 단위·통합 평가, 사람 검토, 평가 지표
10. 구조화 로그, 추적, 관측성
11. 개인정보, 권한 격리, 프롬프트 공격, 안전성 시험

AX Builder가 기술 기반을 점검할 때 유용한 범위다. 특히 모델 사용법에 그치지 않고 평가·운영·보안까지 이어진다는 점을 반영했다.

## AX Engineer 로드맵에서 보완할 영역

AI Agent를 만들 수 있다는 사실만으로 조직의 업무가 바뀌지는 않는다. 다음 책임은 기술 학습 목록만으로 다루기 어렵다.

| 빠진 질문 | AX에서 필요한 이유 |
|---|---|
| 어떤 업무를 먼저 바꿀 것인가 | 가치가 커도 데이터·권한·복구가 준비되지 않으면 운영할 수 없다. |
| 없애거나 단순화할 단계는 무엇인가 | 낭비가 포함된 기존 절차를 그대로 자동화하지 않아야 한다. |
| 어떤 데이터가 사실의 기준인가 | 문서 검색 결과와 실제 주문·재고·승인 상태를 같은 사실로 취급할 수 없다. |
| 누가 승인하고 책임지는가 | “사람이 검토”한다는 문장만으로 권한과 책임이 정해지지 않는다. |
| 실패하면 어디서 멈추는가 | 외부 실행, 금전, 인사, 고객 영향이 있는 업무는 복구와 수동 대체가 필요하다. |
| 공식 업무로 어떻게 채택되는가 | 새 도구가 생겨도 SOP, KPI, 역할, 지원 체계가 그대로면 이중 업무가 남는다. |
| 두 번째 업무에서 무엇을 재사용하는가 | 첫 사례의 코드와 화면을 곧바로 전사 표준으로 만들 수 없다. |

따라서 이 로드맵은 기술 기반을 8단계 업무 전환 생애주기 안에 넣는다. 기술은 독립된 종착점이 아니라 업무 문제를 안전하게 해결하는 수단이다.

## 한국 조직에서 추가로 확인할 조건

한국 기업을 하나의 문화로 단정하지 않는다. 다만 공개 정책과 현장 적용 조건을 고려하면 다음 질문을 별도로 드러낼 필요가 있다.

### 디지털 기반의 격차

중소벤처기업부가 인용한 2024년 조사에서는 중소기업과 대기업, 비수도권과 수도권 기업 사이의 AI 활용률 격차가 나타났다. 다른 중소 제조기업 조사에서는 초기 비용, 인력 부족, 전략 부재가 주요 도입 장애로 제시됐다. 모든 독자가 API와 데이터 기반을 이미 갖췄다고 가정하면 저디지털 조직은 첫 단계부터 이탈한다.

이 저장소는 조직을 업종이나 규모로 단정하지 않고, 현재 업무 기록·원본 시스템·접근 권한·운영 책임의 준비 상태로 시작점을 나눈다.

### 결재선과 실제 의사결정권

직급표가 아니라 실제로 범위를 정하고, 데이터를 허용하고, 배포를 승인하고, 장애 시 중단할 권한이 누구에게 있는지 적는다. 개인 이름 대신 역할을 기록해 인사 이동 뒤에도 운영 책임이 남게 한다.

### 개인정보와 AI 거버넌스

개인정보보호위원회의 생성형 AI 개인정보 처리 안내는 목적 설정부터 데이터 출처 검증, 접근 통제, 배포 전 시험, 투명성, 개인정보 보호책임자 중심의 내부 관리까지 수명주기 전체를 다룬다. 보안 검토를 출시 직전 서류 절차로만 두지 않는 근거다.

인공지능기본법 시행령은 2026년 7월 21일부터 시행 중이며, 고영향·생성형 AI 제품과 서비스의 투명성 의무와 내부 업무 적용 예외 등을 규정한다. 실제 적용 여부는 법무·개인정보·보안 책임자와 현재 법령을 다시 확인해야 한다. 이 로드맵은 법률 자문을 대신하지 않는다.

### 도입보다 공식 업무 전환

좌석 수, 로그인 수, 생성 건수만으로 AX 채택을 판단하지 않는다. 완료 시간, 수정 부담, 예외 처리, 지원 요청, 기존 절차의 종료 여부를 함께 본다. 현장 사용자와 지역·부서별 챔피언이 검수와 지원 설계에 참여해야 한다.

### 공급자 의존과 종료 계획

조달 단계에서 서비스 계정 소유권, 데이터 반출, 로그 보존, 모델·공급자 교체, 계약 종료 후 데이터 삭제와 수동 업무 복귀를 확인한다. 구매 결정과 운영 복구를 한 문서에서 연결한다.
