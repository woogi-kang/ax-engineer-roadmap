# 직무 로드맵

이 디렉터리는 조직 내부 AX Engineer가 맡는 책임과 숙련도를 설명한다. 협업 상대의 책임은 [협업 역할 안내](../tracks/README.md)에서, 구현에 필요한 학습 내용은 [기술 역량](../technical-foundations/README.md)에서 확인한다.

## 로드맵을 이루는 일곱 축

이 저장소의 숫자와 단계는 하나의 점수나 순차 과정이 아니다. 같은 업무를 서로 다른 질문으로 본다.

| 축 | 확인하는 질문 | 범위 |
|---|---|---|
| 업무 전환 단계 | 업무가 어디까지 진행됐는가? | 목표·현재 흐름·재설계·데이터·통제·배포·현업 정착·확장 8단계 |
| 역량 지도 | 무엇을 할 수 있어야 하는가? | 사업성·업무·데이터·통합·AI·운영·현업 정착·조직 학습 8영역 |
| 프로젝트 `P1~P5` | 어떤 수준의 실행 근거를 만들었는가? | 보조 → 승인 → 샌드박스 → 제한 운영 → 두 번째 업무 재사용 |
| 자율성 `A0~A4` | AI에 어느 정도 행동 권한을 주는가? | 사람 수행 → 제안 → 제한된 다단계 수행 → 승인 뒤 실행 → 제한적 자동 실행 |
| 근거 단계 | 공개할 수 있는 근거가 무엇인가? | 실행 설계 → 공개 시뮬레이션 → 익명화 실습 → 제한 파일럿 → 운영 근거 |
| 개인 숙련도 | 한 사람이 맡을 수 있는 책임은 어디까지인가? | Foundation → Builder → Operator → Lead |
| 조직 성숙도 `M0~M4` | 여러 업무에서 같은 운영 능력을 반복할 수 있는가? | 개인 실험 → 제한된 반복 → 운영 가능 → 공통화 → 지속 개선 |

예를 들어 고위험 업무는 조직이 `M4`여도 자율성을 `A1`에 둘 수 있다. 사례 문서가 `ready`이고 설계가 P1~P5를 다루더라도 현재 근거가 `simulation-design`이면 실제 실행이나 조직 성과를 뜻하지 않는다.

## 읽는 원칙

- 직무 이름보다 실제 책임 범위를 본다.
- 기술을 사용한 경험과 운영 결과를 만든 경험을 구분한다.
- 숙련도를 연차나 도구 개수로 판단하지 않는다.
- 모든 역량은 확인 가능한 산출물이나 운영 기록으로 연결한다.
- 비개발자와 개발자가 같은 깊이의 코드를 배울 필요는 없지만, 각자 맡은 승인·검수·구현·운영 경계를 설명해야 한다.
