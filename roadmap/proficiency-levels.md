# 숙련도 기준

## 1. 연차 대신 책임 범위를 본다

AX Engineer 숙련도는 특정 기술을 사용한 기간보다 다음 질문으로 판단한다.

Foundation부터 Lead까지의 단계는 검증된 산업 표준이나 채용 등급이 아니다. 다음 학습과 책임 범위를 고르기 위해 이 저장소가 제안하는 작업 모델이다.

- 모호한 문제를 어디까지 스스로 정리할 수 있는가?
- 어디까지 직접 배포하고 운영할 수 있는가?
- 실패와 위험을 어떤 방식으로 통제하는가?
- 다른 사람과 조직이 결과를 이어받을 수 있는가?
- 한 사례의 학습을 어디까지 재사용할 수 있는가?

## 2. 네 단계

### Foundation

대상 사용자, 권한, 결과 범위를 제한한 업무를 분석하고 안전한 프로토타입을 검증한다.

- 주어진 문제에서 사용자·입력·출력·성공 기준을 정리한다.
- 공개 또는 비민감 데이터로 범위를 작게 잡은 기능을 만든다.
- 정상 사례와 기본 실패 사례를 평가한다.
- 아직 운영 권한과 업무 절차 변경을 단독으로 맡지 않는다.

대표 결과물:

- 업무 발굴 카드
- 제한된 프로토타입
- 평가 사례와 결과
- 명시된 가설·제약·이번 범위에서 제외한 목표

### Builder

한 업무를 기존 시스템에 통합하고 운영 가능한 상태로 배포한다.

- 현업과 범위·우선순위·중단 조건을 합의한다.
- 인증·권한·실패 처리·감사 기록을 포함해 배포한다.
- 사용자 검수와 운영 인수인계를 수행한다.
- 업무 지표와 모델 지표를 나눠 측정한다.

대표 결과물:

- 운영 배포와 재현 가능한 코드
- 업무 실행 규칙·데이터 계약
- 평가·복구 기록
- 사용자 검수와 인수인계 문서

### Operator

배포된 업무의 품질·비용·안정성과 실제 사용 현황을 지속해서 관리한다.

- 장애와 품질 저하를 탐지하고 복구한다.
- 권한·비용·평가 기준의 변경을 관리한다.
- 현업이 직접 조정할 영역과 엔지니어링 영역을 구분한다.
- 기존 수동 절차의 종료 또는 유지 결정을 지원한다.
- 검증된 실행 규칙과 구성 요소를 인접한 두 번째 업무에서 재사용하고 호환성을 관리한다.

대표 결과물:

- 운영 지표와 SLO
- 장애·복구·회귀 평가 기록
- 실제 사용과 업무 결과 검토
- 변경·버전·권한 이력
- 사례 간 재사용과 호환성 기록

### Lead

여러 업무와 팀에서 확인한 실행 규칙을 조직 공통 역량으로 만든다.

- 업무 포트폴리오와 투자 순서를 관리한다.
- 공통 하네스와 팀별 자율성의 경계를 정한다.
- 보안·데이터·현업·플랫폼 책임자가 함께 판단하고 실행할 협업 구조를 만든다.
- 반복되는 실패 원인과 운영 피드백을 공통 기반 로드맵에 반영한다.
- 중앙 팀이 병목이 되지 않는 운영 모델을 만든다.

대표 결과물:

- 여러 사례의 비교와 재사용률
- 조직 공통 완료 기준표
- 공통 실행 규칙·평가 체계·감사 기록 방식
- 현업이 직접 운영한 기록과 역할 전환 기록

## 3. 역량별 기대 수준

| 역량 | Foundation | Builder | Operator | Lead |
|---|---|---|---|---|
| 문제 발견 | 주어진 문제를 구조화 | 현업과 한 업무의 범위 합의 | 운영 중인 업무를 개선·중단 | 조직 포트폴리오와 투자 기준 설계 |
| 업무 설계 | 현재 흐름 작성 | 목표·예외 흐름 구현 | 공식 절차와 역할 전환 | 여러 팀의 공통 규격 |
| 데이터 | 제한된 데이터 계약 | 원본·가공·결과의 관계와 계보 | 품질·최신성·계보 운영 | 조직 공통 용어·지표와 소유권 |
| 소프트웨어 | 프로토타입과 테스트 | 한 업무의 운영 배포와 통합 | 신뢰성·비용·변경·호환성 운영 | 여러 팀의 재사용 기반과 확장 정책 |
| Applied AI | 기본 평가 | 회귀·안전·담당자에게 넘기기 | 운영 평가와 품질 개선 | 평가 표준과 모델 전략 |
| 보안·운영 | 위험 식별 | 권한·로그·복구 구현 | 장애·SLO·비용 운영 | 조직 통제 체계 |
| 실제 업무 적용 | 사용자 피드백 | 검수·교육·인수인계 | 실제 사용과 기존 절차 종료 | 현업이 직접 운영하고 개선하는 체계 |
| 표준화 | 재사용 후보 기록 | 한 업무 안에서 템플릿화 | 두 번째 업무 재사용과 버전 운영 | 조직 공통 기반 로드맵 반영 |

### 수준을 판정할 때 남길 기록

| 수준 | 추가로 확인할 증거 |
|---|---|
| Foundation | 개발에 쓰지 않은 입력의 평가, 구현자 외 검수, 거절·보류의 근거 |
| Builder | 승인 대기·권한 회수·중복·부분 성공 시험, 실제 사용자 검수와 운영 인수인계 |
| Operator | 재접속·실제 취소·정책 서버 장애·롤백 훈련, 완료 업무당 총비용, 변경 뒤 회귀·재검수 |
| Lead | 업무별 확대·중단 결정, 정책 예외와 기한, 현업의 직접 운영과 역할 전환, 여러 업무의 변경 영향 |

교육 이수나 평가 항목 작성만으로 수준이 올라가지는 않는다. 수행 환경, 판정자 역할, 최초 평가와 재평가 결과를 함께 제시한다. 공개 시뮬레이션만 수행했다면 실제 배포·조직 운영 책임은 미검증으로 남긴다. 다음 단계로 넘어갈 때는 새 시나리오로 확인하고 실패를 고친 뒤에는 기존 회귀 평가도 다시 수행한다.

## 4. 승급이 아닌 성장 판단

다음 수준으로 이동하려면 모든 기술을 새로 배울 필요는 없다. 현재 수준에서 부족한 **책임과 결과물**을 하나씩 추가한다.

예시:

```text
Foundation → Builder
프로토타입에 인증·권한·실패 처리·배포·사용자 검수를 추가한다.

Builder → Operator
한 번의 배포를 4주 이상 운영하며 품질·비용·장애·실제 사용 변화를 기록한다.

Operator → Lead
두 개 이상 업무에서 검증한 실행 규칙을 여러 팀이 쓰는 기반과 운영 모델로 확장한다.
```

직함이 높아도 해당 책임을 수행한 결과물이 부족할 수 있고, 직함 없이 Lead 수준의 책임을 맡을 수도 있다. 이 기준은 사람을 평가하기보다 다음 학습과 실습을 선택하는 데 사용한다.
