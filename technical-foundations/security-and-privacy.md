# 보안과 개인정보

## 왜 필요한가

LLM 시스템은 자연어를 명령과 데이터의 경계에서 사용한다. 신뢰할 수 없는 문서나 메시지가 도구 호출을 유도할 수 있고, 넓은 권한과 과도한 데이터 보관은 작은 모델 오류를 큰 업무 사고로 바꾼다. 보안과 개인정보는 배포 직전 검토가 아니라 목적 설정부터 운영 종료까지 함께 설계해야 한다.

## 알아야 할 것

- 데이터 분류, 처리 목적, 최소 수집, 보유·삭제
- 인증, 인가, 최소 권한, 서비스 계정
- 직접·간접 프롬프트 공격
- 민감정보 노출과 안전하지 않은 출력 처리
- 과도한 기능·권한·자율성
- 공급망과 외부 모델·도구
- 샌드박스, 허용 목록, 속도·비용 제한
- 위협 모델, 보안 시험, 사고 대응
- 정보주체 권리, 투명성, 내부 거버넌스

## 선택할 조건

### 데이터를 보낼 수 있는가

업무상 편리함보다 처리 목적, 데이터 종류, 적법 근거, 계약, 저장 위치, 보유·학습 조건, 삭제 방법을 먼저 확인한다. 익명화·가명화로 충분한지, 원본 조회 대신 최소 필드만 보낼 수 있는지 검토한다.

### 어떤 권한을 줄까

기능을 기준으로 읽기·제안·승인 요청·쓰기·삭제를 분리한다. 모델이 사용할 수 있는 도구 수와 인자 범위를 제한한다. 사용자 권한을 그대로 위임하지 않는다.

### 프롬프트 공격을 어떻게 볼까

모델에게 “외부 지시를 무시하라”고 쓰는 것만으로 막지 않는다. 신뢰 경계를 표시하고, 외부 콘텐츠를 명령과 분리하며, 도구 인자를 검증한다. 고위험 실행은 코드나 정책으로 정한 규칙과 담당자 승인을 거친다.

## 직접 해볼 것

1. 데이터 흐름과 신뢰 경계를 그린다.
2. 자산, 공격자, 오용, 영향을 위협 모델에 적는다.
3. 외부 문서·메일에 숨긴 지시로 도구 호출을 유도한다.
4. 권한 상승, 민감정보 요청, 금지 대상 실행을 시험한다.
5. 최소 권한 서비스 계정과 샌드박스에서 공격을 재현한다.
6. 로그의 민감정보 마스킹, 보유·삭제, 접근 통제를 확인한다.
7. 사고 시 자동 실행 차단과 보고 절차를 훈련한다.

## 확인할 결과

- 데이터 흐름과 처리 목적
- 위협 모델과 위험 소유자
- 역할·서비스 계정 권한표
- 공격·오용 평가 세트와 결과
- 샌드박스·허용 목록·한도 설정
- 보유·삭제·정정·접근 절차
- 사고 대응과 개선 기록

## 실패 패턴

- 프롬프트 문구 하나를 보안 경계로 사용한다.
- 모델이 쓰지 않는 기능까지 도구에 노출한다.
- 개인 계정의 넓은 권한을 자동화에 사용한다.
- 모든 입력과 출력을 무기한 저장한다.
- 연결 표준이나 공급자 인증이 업무 승인까지 해결한다고 본다.
- 법률 문구를 일반화해 실제 적용 검토를 생략한다.

## 함께 합의할 사람

- 업무 책임자: 금지 행동과 허용 위험
- 데이터 소유자·개인정보 책임자: 처리 목적과 수명주기
- 보안 담당자: 위협·권한·시험
- 법무 담당자: 현재 법령·계약 적용
- 운영 담당자: 차단·복구·사고 보고
