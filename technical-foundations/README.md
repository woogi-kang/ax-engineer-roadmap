# AX 엔지니어의 기술 역량

AX 엔지니어가 업무 시스템을 안전하게 만들고 운영하려면 어떤 기술을 알아야 하는지 정리한다. 제품과 프레임워크 이름을 나열하기보다, 실제 업무에서 내려야 할 기술적 판단과 검증 방법을 다룬다.

## 먼저 적용할 원칙

복잡한 구조가 더 높은 숙련도를 뜻하지 않는다.

```text
규칙 기반 처리
→ 검색·분류
→ 초안·제안
→ 담당자 승인 후 실행
→ 범위가 제한된 자동 실행
→ 필요한 경우에만 Agent Loop
```

더 단순한 방식이 성공 기준을 충족하면 그 방식을 유지한다. 모델·프레임워크·클라우드 이름은 현재 구현 선택지일 뿐 핵심 역량이 아니다.

## 실습에서 함께 확인할 기준

아래 문서는 구현 과제와 통과 기준을 안내한다. 문서를 보완했다는 사실만으로 실제 연동이나 운영 검증을 마쳤다고 표시하지 않는다.

- 모델 호출, 도구 실행, 상태 복구를 묶는 실행 코드(harness)도 버전으로 관리한다. 모델·API·SDK·도구·프롬프트·컨텍스트 정책을 바꿀 때 같은 평가 세트로 비교한다.
- 실행이 오래 걸리면 작업 식별자와 상태를 저장한다. 추가 입력, 승인 만료, 재접속, 취소 요청, 외부 결과 대사를 시험한다.
- 결과 문장과 원본 시스템의 최종 상태를 따로 확인한다. 여러 번 실행한 결과와 실패도 함께 남긴다.
- 비용은 [검수 통과 완료 업무당 총비용](production-operations.md#완료-업무당-총비용)으로 비교한다. 실패·재시도·사람의 검수와 재작업을 계산에서 빼지 않는다.

공식 명세, 선택적 확장, 공급자의 beta 기능, 향후 제안은 상태를 구분한다. 사용하려는 Host·Server·SDK의 지원 여부와 확인일은 구현을 시작할 때 다시 기록한다.

## 역할에 따라 필요한 깊이

- **AX 엔지니어**: 직접 구현하고 시험하며 배포·운영 기록을 남긴다.
- **현업 실무자**: 업무 기준, 결과 검수, 담당자 승인 범위를 설명한다.
- **리더·의사결정자**: 투자·책임·공급자·중단 결정에 필요한 질문을 한다.
- **데이터·보안·운영 담당자**: 데이터 사용, 접근 권한, 관측, 사고 대응 기준을 함께 설계한다.

## 각 문서에서 확인할 것

각 문서는 같은 질문을 따른다.

```text
왜 필요한가
무엇을 알아야 하는가
어떤 조건에서 무엇을 선택하는가
무엇을 직접 해볼 것인가
어떤 결과와 기록을 남길 것인가
어떤 실패를 피할 것인가
누구와 합의할 것인가
어떤 출처를 확인했는가
```

읽기만으로 완료하지 않는다. [실습 프로젝트](../projects/README.md)에서 업무 제약과 실패를 재현한다.
