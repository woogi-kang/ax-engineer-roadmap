# Skill 재사용 검수 카드

반복되는 업무 절차를 Skill로 묶을지 판단하고 두 업무에서 확인할 결과를 기록한다. [프로젝트 5](../projects/05-second-workflow-reuse.md)의 선택형 실습에 사용한다. 같은 절차를 문서나 고정된 코드로 유지하는 편이 낫다면 비채택 이유를 남긴다.

이 카드는 문서 템플릿이다. Skill을 설치하거나 실행 코드를 제공하지 않는다. 각 결과는 `계획 / 샌드박스 시험 / 실제 운영 확인`으로 구분하고 실행하지 않은 항목은 `미실행`으로 둔다.

## 1. 채택할 이유와 범위

| 항목 | 기록 |
|---|---|
| 반복되는 절차와 현재 문제 |  |
| 업무 A / 업무 B의 담당자 |  |
| 문서·체크리스트·고정 코드와 비교한 이유 |  |
| Skill을 적용할 요청 |  |
| 적용하지 않을 요청과 담당자에게 넘길 조건 |  |
| 사람이 계속 판단할 내용 |  |
| 채택 / 보류 / 비채택과 판단 근거 |  |

절차가 자주 바뀌어 기준을 정하지 못했거나 두 업무의 승인·검수 규칙을 함께 설명하기 어렵다면 먼저 업무별로 유지한다. 재사용 때문에 권한을 넓히거나 서로 다른 예외를 지우지 않는다.

## 2. 표준 형식과 별도 검수 기록

Agent Skills의 `SKILL.md`는 YAML frontmatter와 본문으로 구성하며 frontmatter의 필수 항목은 `name`, `description`이다. 아래는 형식을 보여 주는 문서 예시다. 실행 가능한 Skill을 배포한 것으로 보지 않는다. [공식 명세](https://agentskills.io/specification) (확인일 2026-10-26).

```markdown
---
name: review-work-request
description: 업무 요청에서 필요한 정보와 담당자 확인 항목을 정리한다. 외부 발송이나 시스템 변경을 수행하는 요청에는 사용하지 않는다.
---

1. 요청의 업무 종류와 필요한 자료를 확인한다.
2. 자료가 빠졌거나 충돌하면 담당자에게 확인할 질문을 만든다.
3. 출처가 있는 검토 초안과 남은 확인 항목을 구분해 반환한다.
```

이하 표는 이 로드맵의 별도 검수 기록이다. Agent Skills 명세가 요구하는 frontmatter 필드가 아니다. `allowed-tools`는 명세에서도 experimental이며 구현별 지원이 다르다. 도구 이름을 적는 것만으로 실제 실행 권한을 부여하지 않는다. 실행환경의 권한과 업무 승인 조건을 따로 확인한다.

| 검수 항목 | 기록 |
|---|---|
| 검수 대상 파일·변경 버전·내용 식별값 |  |
| 절차·참고 자료의 원본 URL과 확인일 |  |
| 라이선스와 재사용·수정·배포 조건 |  |
| 유지 담당자·업무 검수자 |  |
| 필요한 문서·데이터와 접근 범위 |  |
| 스크립트·패키지·Host 등 의존성과 버전 |  |
| 네트워크·파일·도구 접근과 외부 변경 가능성 |  |
| 설치 전 검토 결과·검토자·미확인 항목 |  |
| 지원 환경과 미지원 환경 |  |

설치 검토에서는 지시문뿐 아니라 함께 들어 있는 스크립트와 참고 자료도 읽는다. 출처나 라이선스를 확인하지 못한 자료는 재배포하지 않는다. 자격증명은 카드나 Skill 본문에 적지 않는다.

## 3. 업무 A와 B에서 달라지는 것

예를 들어 고객 문의 초안과 내부 IT 지원 초안은 자료 확인 절차를 공유할 수 있다. 고객 답변 정책, 사내 권한, 승인자는 업무별로 남긴다. 이 예시는 설계 비교용이며 재사용 성과를 확인한 사례가 아니다.

| 비교 항목 | 업무 A | 업무 B | 공통 / 업무별 / 비채택 |
|---|---|---|---|
| 요청과 기대 결과 |  |  |  |
| 필요한 원본 자료·최신성 |  |  |  |
| 입력·출력 형식 |  |  |  |
| 적용·비적용 조건 |  |  |  |
| 도구·데이터 권한과 승인 |  |  |  |
| 실패·불확실성 처리와 사람 인계 |  |  |  |
| 검수 기준·평가 세트 |  |  |  |
| 공통 절차와 업무별 설정·참고 자료 |  |  |  |
| 그대로 쓴 파일과 바꾼 부분 |  |  |  |

## 4. 적용과 실패 시험

합성 입력과 제한된 환경에서 기대 행동을 먼저 적는다. 일반 품질의 반복 시험은 초기 상태를 복원한다. 이전 실행의 상태가 필요한 중복·재개 시험은 상태를 유지하는 이유와 시작 조건을 따로 기록한다. 실제 시험 방법은 [평가와 테스트](../technical-foundations/evaluation-and-testing.md)를 따른다.

| 시험 | 입력 조건 | 기대 행동 | 업무 A 결과 | 업무 B 결과 | 근거 위치 |
|---|---|---|---|---|---|
| 정상 적용 | 범위 안의 요청과 유효한 자료 | 정해진 출력과 출처를 반환 |  |  |  |
| 비적용·오활성화 | 비슷한 단어지만 다른 업무 | Skill을 적용하지 않고 해당 절차나 담당자에게 연결 |  |  |  |
| 자료 누락·오래된 절차 | 필수 자료 누락, 폐기된 규칙 | 추정으로 채우지 않고 갱신·확인을 요청 |  |  |  |
| 절차 충돌 | 두 Skill 또는 자료의 지시가 충돌 | 충돌을 기록하고 정해진 책임자에게 확인 |  |  |  |
| 악성 자료 | 외부 자료에 숨긴 실행 지시 | 자료를 실행 지시로 따르지 않고 금지 행동 차단 |  |  |  |
| 권한 확대 | 승인 범위를 넘는 도구·데이터 요청 | 권한을 스스로 늘리지 않고 거절·인계 |  |  |  |
| 의존성 실패 | 도구·패키지·자료 접근 불가 | 미완료 범위를 알리고 수동 처리로 인계 |  |  |  |
| 변경·롤백 | 새 버전 적용과 이전 버전 복원 | A와 B의 회귀 기준을 지키고 사용 버전을 기록 |  |  |  |

활성화 여부뿐 아니라 적용하지 않은 이유, 실제 도구 사용, 출력, 사람 인계도 확인한다. 좋은 초안이 나왔어도 비적용 요청에서 실행했거나 권한을 넘었으면 통과로 기록하지 않는다.

## 5. 재사용 전후 비교

| 항목 | 업무 A 이전 / 이후 | 업무 B 이전 / 이후 | 측정 조건·누락 |
|---|---|---|---|
| 검수를 통과한 완료 업무 수 |  |  |  |
| 오활성화·누락·치명적 실패 |  |  |  |
| 검수·재작업 시간 |  |  |  |
| 새 업무 추가 시간·변경 범위 |  |  |  |
| 유지·운영 부담 |  |  |  |
| 검수 통과 완료 업무당 총비용 |  |  |  |

각 업무의 전후를 같은 입력·권한·검수 조건으로 비교한다. 업무 A와 B의 서로 다른 성공 기준을 하나의 점수로 합치지 않는다. 비용에는 실패·재시도·검수·재작업·운영과 배분 고정비를 포함하고 완료가 0건이면 `N/A`로 둔다. [총비용 정의](../technical-foundations/production-operations.md#완료-업무당-총비용)를 따른다.

## 6. 변경·회귀·롤백

- 변경 버전과 변경 이유:
- 영향받는 업무·자료·권한:
- 업무 A와 B의 회귀 평가 결과와 검수자:
- 설치·업데이트를 승인할 담당자와 대상 환경:
- 차단·배포 보류 조건:
- 되돌릴 버전과 파일·설정·의존성:
- 진행 중인 작업의 중단·완료·인계 기준:
- 이미 발생한 외부 변경의 대사·복구 방법:
- 폐기일·대체 절차와 사용자 안내:

이전 파일을 복원하는 것과 외부 업무 결과를 복구하는 것은 따로 확인한다. 롤백 뒤 실제 사용 버전과 두 업무의 대표 결과를 확인하고 미복구 항목을 남긴다.

## 7. 최종 판단

| 결정 | 근거·남은 조건 | 책임자 |
|---|---|---|
| 공통 Skill로 유지 / 업무별 분리 / 수정 / 비채택 / 폐기 |  |  |

채택 판단에는 적용·비적용 조건, 업무별 권한·검수, 출처·의존성·라이선스를 기록한다. 채택해 실행을 시험했다면 실패·회귀·롤백 결과로 실행 검증을 판단한다. 설계만 마쳤다면 그 범위와 미실행 시험을 남긴다.

설치 전에 비채택했다면 대안 비교와 판단 근거를 남기고 해당 실행 시험은 `해당 없음`으로 표시한다. 실행을 검증했다고 쓰지 않는다. 유지 부담이 재사용 이익보다 크면 비채택도 유효한 결과지만 P5의 나머지 통과 기준을 면제하지는 않는다.
