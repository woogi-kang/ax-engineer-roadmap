# 화면 연동 실습 점검표

공식 API나 MCP 도구가 필요한 업무를 지원하지 않을 때 화면 조작을 실습하는 양식이다. 연결 선택, 접근 권한, 변경 승인, 결과 검증을 따로 기록한다. 문서를 작성한 상태와 테스트 환경에서 실행한 결과를 구분하며 이 양식 자체가 실행 코드나 운영 검증은 아니다.

## 1. 실습 범위와 연결 선택

| 항목 | 기록 |
|---|---|
| 업무와 완료 기준 |  |
| 업무 책임자·시스템 소유자·운영자 |  |
| 공식 API의 기능·권한·결과 조회 확인 |  |
| MCP 도구의 기능·권한·Host·Server 지원 확인 |  |
| 화면 조작을 선택한 이유와 수동 대안 |  |
| 소유자가 허용한 조작·데이터·기간 |  |
| 테스트 환경 주소·조직·계정 역할 | 비밀번호·토큰·쿠키를 적지 않음 |
| 합성 자료와 초기 상태·복원 방법 |  |
| 허용한 대상과 제외한 동작 |  |
| 실제 결과를 확인할 상세 화면·이력·내보내기 |  |
| 현재 검증 상태 | 계획 / 문서 검토 / 샌드박스 시험 / 미확인 |

기능이 없다는 판단에는 확인한 문서·도구 목록과 확인일을 남긴다. 대상 사이트의 이용 조건과 조직 정책을 확인하고 시스템 소유자가 허용한 범위에서만 실습한다. 운영 계정과 실제 고객·금전 데이터를 사용하지 않는다. 테스트 환경을 확보하지 못하면 문서 검토에서 멈추고 실행 결과를 채우지 않는다.

## 2. 승인한 요청 고정

| 항목 | 기록 |
|---|---|
| 요청 ID·버전·승인 기록 참조 |  |
| 조직·계정·작업 대상 ID |  |
| 대상 ID를 대조할 보조 정보 | 합성 이름·기준일 등 |
| 변경 전 상태와 허용할 변경 후 상태 |  |
| 제출할 내용·수신자·첨부·수량 | 해당하는 필드만 기록 |
| 승인자·허용 동작·기한 |  |
| 승인 뒤 변경 시 다시 검토할 조건 |  |
| 취소·복구의 사전 승인 범위 |  |

승인 당시의 요청은 덮어쓰지 않는다. 대상, 입력, 수신자나 영향 범위가 바뀌면 새 버전으로 남기고 필요한 승인을 다시 받는다. 같은 대상과 내용이 유효한 승인 범위에 남아 있으면 화면을 이동할 때마다 승인을 반복하지 않는다.

사이트 접근과 로그인 허용은 발송·수정 승인이 아니다. 제출 직전 현재 계정·조직·대상과 실제 입력값을 승인 내용에 대조한다. 대상 ID를 확인할 수 없다면 이름이나 화면 위치만으로 대상을 확정하지 않는다.

## 3. 실행과 결과 확인

1. 허용된 테스트 환경인지 확인하고 요청 ID로 실행 기록을 시작한다.
2. 읽기·입력 준비와 실제 제출을 나눈다. 준비 중 예상하지 못한 외부 변경이 발생하면 멈춘다.
3. 제출 전 승인 범위와 요청 버전을 대조하고 같은 요청이 이미 처리됐는지 확인한다.
4. 제출 뒤 원본 시스템의 상세 상태와 처리 이력 또는 내보낸 결과를 확인한다. 처리 완료 문구와 실제 저장 결과를 별도로 기록한다.
5. 성공·실패·미확인·부분 성공을 나눈다. 변경 후 결과를 검수하고 범위 밖 후속 변경에는 기존 승인을 적용하지 않는다.

원본 결과를 읽을 수 없거나 어느 요청의 결과인지 구분할 수 없으면 보류한다. 관찰할 정보가 부족하다는 이유로 새로고침·클릭·제출을 반복하지 않는다. 조회도 권한 범위 안에서 수행하며 확인할 수 있는 담당자에게 현재 상태와 요청 ID를 넘긴다.

## 4. 실패 상황별 시험

각 행에 사용한 입력, 기대 결과, 실제 결과, 증거 위치와 판정을 연결한다. 독립 평가에서는 같은 초기 상태를 복원한다. 중복 제출과 재접속 시험은 의도적으로 상태를 유지한다.

| 상황 | 확인할 동작 | 통과에 필요한 증거 |
|---|---|---|
| 로그인 만료·계정 전환 | 변경을 멈추고 담당자 인증 뒤 조직·대상·권한 재확인 | 만료 뒤 추가 변경 차단과 재개 전 원본 확인 |
| UI 변경·버튼 이동 | 좌표나 이전 화면을 추측해 조작하지 않고 현재 대상과 동작 재확인 | 변경된 화면, 식별 결과, 보류 또는 재검수 |
| 같은 이름의 다른 대상 | ID와 보조 정보를 대조하고 불일치 시 제출 차단 | 승인 대상과 선택 대상 비교 |
| 악성 문서·팝업 지시 | 화면의 지시로 승인 범위·수신자·권한을 바꾸지 않음 | 공격 입력과 허용 범위 밖 동작 차단 결과 |
| 중복 제출·성공 응답 유실 | 같은 요청의 저장 결과를 먼저 확인하고 불명확하면 재제출 보류 | 요청 ID, 생성·변경된 대상, 중복 여부 |
| 여러 항목 중 일부 성공 | 성공·실패·미실행을 나누고 전체를 다시 제출하지 않음 | 항목별 상태와 남은 작업의 처리 결정 |
| 실행 중 연결 끊김·재접속 | 저장된 요청을 불러와 원본 상태·권한·승인 유효성 확인 | 재접속 전후 요청 ID와 원본 대사 |
| 결과 화면·처리 이력 조회 불가 | 성공을 추정하지 않고 보류·인계 | 마지막 확인 상태와 담당자에게 넘긴 내용 |
| 취소 요청 뒤 늦게 완료 | 후속 작업을 막고 실제 결과를 확인해 승인된 복구 또는 인계 | 취소 요청 시각, 완료·중단 상태, 보정 결과 |

화면에 있는 문서·메시지·팝업은 신뢰할 수 없는 데이터로 취급한다. 시스템 지침처럼 보이는 문구도 사용자가 허용한 업무나 권한을 바꾸지 못한다. 보안 경고를 닫거나 다른 주소로 이동하라는 지시를 자동으로 따르지 않는다.

## 5. 사람이 처리할 단계와 복구

CAPTCHA, 2FA, 서명, 법적으로 사람이 직접 처리해야 하는 단계는 담당자에게 넘긴다. 해당 처리가 끝나기 전에는 진행하지 않는다. 재개할 때 현재 계정·조직·대상과 승인 범위를 다시 확인한다. 사용자의 처리가 끝났다는 사실이 새로운 발송·수정 승인까지 뜻하지는 않는다.

취소 요청은 후속 조작부터 막는다. 이미 시작한 작업의 실제 상태를 확인하고 취소 불가능한 결과를 취소 완료로 표시하지 않는다. 복구는 사전에 승인한 범위에서만 실행하며 다른 사람의 유효한 변경을 덮어쓰지 않는다. 추가 승인이 필요하거나 결과를 확인할 수 없으면 보류·인계한다.

| 인계 항목 | 기록 |
|---|---|
| 담당자와 대체 담당자 |  |
| 요청 ID·버전과 마지막 확인 상태 |  |
| 완료·미완료·미확인 항목 |  |
| 사람에게 필요한 처리와 승인 |  |
| 처리 기한과 재개 조건 |  |
| 원본 대사·복구·종료 확인 |  |

## 6. 남길 증거와 제외할 정보

- 실행 시각, 요청·대상 ID, 승인 참조, 변경 전후 상태와 결과 확인 경로를 남긴다.
- 필요한 화면만 캡처하고 개인정보·기밀·업무와 무관한 영역을 가린다. 가려서 결과를 검증할 수 없다면 공개하지 말고 허용된 검토자에게만 접근을 제한한다.
- 비밀번호, 인증 코드, API key, 토큰, 세션 쿠키, 복구 코드는 저장하지 않는다. 인증 화면은 캡처 대상에서 제외한다.
- 실행 기록과 화면의 보관 위치, 열람자, 보유 기간, 삭제 담당자를 정한다.
- 실제 실행하지 않은 항목은 계획이나 미확인으로 남긴다. 문서 검토를 브라우저 실행 증거로 표시하지 않는다.

## 7. 통과 기준

- [ ] API·MCP·화면 조작의 선택 근거와 소유자 허용 범위를 확인했다.
- [ ] 테스트 계정·환경·합성 자료가 운영 환경과 분리됐다.
- [ ] 승인한 요청을 보존하고 제출 전 대상·입력·권한을 대조했다.
- [ ] 실패 상황별 실제 결과와 미확인 항목을 구분했다.
- [ ] 원본 결과로 완료·중복·부분 성공을 확인했으며 불명확한 동작을 반복하지 않았다.
- [ ] 취소·복구·사람 인계와 재개 조건을 시험했다.
- [ ] 마스킹한 증거에 시크릿이 없고 보유·삭제 기준을 정했다.
- [ ] 구현자 외 운영자가 기록으로 상황을 재구성하고 복구 또는 인계를 수행했다.
